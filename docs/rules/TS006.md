# TS006 bounded-loops

The severity is warning; the rule is on by default and stable.

## Reports

A loop carries an upper bound, so it cannot run forever on unexpected input, and a loop
that is meant to run forever says so in an assertion right before it.

Reporting unit: Each loop.

Anchor: The loop keyword, or the `do` of a `do { } while` loop.

Carve-outs: A loop over a finite sequence is exempt, as is one whose condition names
something the body or the continue expression reassigns. A loop is exempt when the
statement right before it is an assertion whose condition is the literal `true`, `True`,
or `1`, which is the standard's "this loop cannot terminate" assertion, or whose condition
contains the loop's own condition text, such as `assert(running)` before `while (running)`.
An assertion that names something else does not exempt the loop that follows it.

Rust `loop`, Zig `while (true)`, JavaScript `while (1)` and `do { } while (true)`, Python
`while True` and `while 1`, and a three-clause `for` whose condition clause is empty report
as unbounded outright, whether or not the header is parenthesised.

An open range reports: Rust `for x in 0..` and Zig `for (0..) |i|`. Zig `for (items, 0..)`
is bounded by the slice beside the range and is exempt.

A `for ... in` header that reaches a source without an end reports: `repeat`,
`repeat_with`, `from_fn`, `successors`, `cycle`, `recv`, `lines` on `stdin`, and `iter` on a
name declared as a `Receiver`, unless `take` or `zip` bounds the chain. The first four are free
functions, `std::iter::repeat(1)`; called as a method, `0..find.repeat()` or `"ab".repeat(3)`, the
name belongs to another type and is no endless source. A `for` over a name
declared as a channel or a `Receiver` reports, including a dotted path such as `w.ch` whose
last segment is declared as a channel anywhere in the file.

A loop whose whole condition is a call reports, since a call promises no bound: Go `for
s.Scan()` and `for rows.Next()`, Rust `while let Some(x) = stack.pop()` and `while let Ok(v) =
rx.recv()`, Zig `while (it.next()) |x|`, and Python `while f():`. The loop is exempt when its
body carries an assertion or decrements a counter with `-=` or `--`, which is the body asserting
or enforcing the bound, or when the assertion before the loop qualifies as above. A Zig
assertion counts through a file alias too, `try expectEqual(a, b)` under `const expectEqual =
std.testing.expectEqual;`, as TS004 counts it.

A condition that is a name, or a dotted path such as `s.done`, reports when nothing in the
body or the continue expression writes to any segment of it. A segment the body steps with
`++` or `--` counts as reassigned, as one written through a compound assignment does, and
so does a segment that a method is called on, since the call may write it. A name the body
deletes from, Python `del bits[:1]` or JavaScript `delete s.done`, is written, and so is a name in
a target list that opens a statement and unpacks an assignment, `i, n = divmod(i, 36)`, while a
call's keyword argument, `work(ready, n=3)`, writes nothing. A Python `for` whose target is a
parenthesized tuple, `for (label, name), state in models.items():`, iterates like any other `for
... in`: a comma after the opening group continues the header rather than closing it.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

An iterating `for`, one with `in`, `of`, `range`, or a Zig payload capture, is not read as
a condition loop, so a slice it walks is not reported as a name the body never reassigns. A Rust
struct pattern before the `in`, `for Pair { left, right } in pairs {`, is part of that header
rather than the loop's body, so the loop still iterates.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS006, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

A body that reassigns the condition through a function it calls by reference, rather than
through a method on the name, is read as never reassigning it.

The shapes that misfire here are `name-keyed-channel-type`, `node-shape-anchor`, and `dot-directory-walked`.

## Citations

TigerStyle: "All loops and all queues must have a fixed upper bound to prevent infinite
loops or tail latency spikes. [...] Where a loop cannot terminate (e.g. an event loop),
this must be asserted."

NASA P10 Rule 2: "All loops must have a fixed upper-bound. It must be trivially possible
for a checking tool to prove statically that a preset upper-bound on the number of
iterations of a loop cannot be exceeded."
