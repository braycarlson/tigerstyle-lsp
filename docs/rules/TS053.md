# TS053 explicit-options

The severity is info; the rule is opt-in by default and stable.

## Reports

A call spells the options it passes, so a change to the callee's defaults cannot change what the
call does.

Reporting unit: Each empty argument, plus one per Rust struct literal that fills its remaining
fields from a default.

Anchor: The argument, or the `..Default::default()` span.

Carve-outs: An argument reports when, with whitespace ignored, it is an empty literal the language spells for
"use the defaults": Zig `.{}`, Go and Odin `Options{}` or `&pkg.Options{}`, JavaScript, TypeScript,
and Python `{}`, and Rust `Default::default()` or `Options::default()`. The text before the empty
braces has to be a bare path, so a Go `[]int{}` or `map[string]int{}` is a collection and is quiet.
Rust also reports `..Default::default()`, `..Self::default()`, and `..Options::default()` inside a
struct literal, since the fields it does not spell come from the defaults. A struct update through
another type name passes the same suffix test as an argument below, so `..RenderOptions::default()`
reports while `..Profile::default()` builds a value from that type's defaults and is quiet.

An empty literal that follows a string literal argument, or an argument that concatenates one with
`++` or spells a multiline string, is quiet, because that is the argument tuple of a format call:
`std.debug.print("ready", .{})`, `std.log.info("x", .{})`, and `print(head ++ "tail", .{})` pass no
arguments rather than no options. A JavaScript, TypeScript, or Python `{}` reports only as the last
of two or more arguments, which is where an options object goes; an only argument or a middle one is
data being passed rather than options being left out. An argument of a call that compares values,
one whose name carries `equal` in any case or ends in `_eq` or `_ne`, or Odin's `expect_value`, as
`self.assertEqual(form.errors, {})`, `assert.deepEqual(result, {})`, Zig `deepEqual(T, .{}, .{})`,
and Odin `testing.expect_value(t, rex.flags, regex.Flags{})` do, is the value compared rather than
options. A `{}` right after a tuple argument, `process_view(request, view, (), {})` or
`SendCall((request,), {})`, is the keyword half of an `(args, kwargs)` pair. A Python `{}` handed to
a mapping's `get` or `setdefault` is the default value the mapping returns or stores, as the Zig
storing methods below are. A Go, Odin, or Rust literal reports only when
its type name ends in `Options`, `Opts`, `Config`, `Params`, `Args`, `Settings`, or `Flags`, so
`Delimiter{}` and `unsafe.Sizeof(Account{})` are values rather than defaults, while
`Default::default()` and `..Default::default()` with no type name always report. An Odin `{}` with
no type name is quiet: Odin infers the literal's type from the parameter it fills, which is as often
a slice of expected results or a union as an options struct, so `collect_value_decl(exprs, file,
file_tags, stmt, {})` passes an empty `[]^ast.Attribute`. A `&.{}` or `&Options{}` is a pointer to
an empty literal and is quiet. A Zig empty literal passed to a method whose name ends in `Context`
or `Adapted`, `map.getContext(key, .{})`, is the hash context the standard library's containers
take, and is quiet: it builds a context with no fields rather than leaving options at their
defaults. A Zig empty literal passed to a method that stores it, `append`, `appendAssumeCapacity`,
`getOrPutValue`, `insert`, `insertAssumeCapacity`, `put`, `putAssumeCapacity`,
`putAssumeCapacityNoClobber`, or `putNoClobber`, as in `map.getOrPutValue(gpa, tag, .{})`, is the
value stored rather than options left out, and is quiet. A Zig empty literal that fills a parameter
the file itself declares `anytype`, as in `p.err(token, .tag, .{})` against `fn err(p: *Parser,
token: u32, tag: Tag, args: anytype)`, is an empty tuple rather than options left at their defaults,
since an `anytype` parameter declares no fields to default. The callee is matched by name among the
file's own functions, and a call that passes one argument fewer than the function declares is a
method call whose receiver fills the first parameter. Each function of that name whose parameter
count fits the call has to declare `anytype` at the position, so `value.write(.{})` still reports
when one `write` takes `args: anytype` and another takes `options: Options`.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS053, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

A Zig empty tuple that is the argument pack for a function passed beside it, as in
`std.Thread.spawn(.{}, run, .{})`, reports at both positions; the first is the options the rule
wants spelled and the second is the arguments `run` takes, which the rule cannot tell apart. A
JavaScript `Object.assign({}, source)` reports its target object. A Zig empty argument tuple passed
to a parameter typed as a tuple of zero fields, such as a GObject signal's `emit(self, null, .{},
null)`, reports, since the parameter's type is declared in another file. The shapes that misfire
here are `trailing-argument-tuple`, `assign-target-object`, and `empty-argument-tuple`.

## Citations

TigerStyle: "Explicitly pass options to library functions at the call site, instead of relying
on the defaults. For example, write `@prefetch(a, .{ .cache = .data, .rw = .read, .locality = 3
});` over `@prefetch(a, .{});`. This improves readability but most of all avoids latent,
potentially catastrophic bugs in case the library ever changes its defaults."
