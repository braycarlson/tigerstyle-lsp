# TS036 assert-side-effects

The severity is error; the rule is on by default and stable.

## Reports

An assertion only reads state, because a build that strips assertions must run the same
program.

Reporting unit: Each assertion, and an assertion reports only the first offending site inside it.

Anchor: The mutating node.

Carve-outs: Each assertion is in scope, whether or not the release build keeps it: Rust `assert!`,
`assert_eq!`, `assert_ne!`, `assert_matches!`, and `debug_assert*!`, Zig `std.debug.assert` and the
`std.testing.expect*` family, whether a call spells its full path or a file alias such as `const
expect = std.testing.expect;`, and each Go, Python, JavaScript, TypeScript, and Odin assertion. P10
says always. An assertion the release build keeps is reported with the note that it runs in release
builds too, since its effect ships. A Python `def` or `class` that declares a name shaped like an
assertion declares it rather than calling it, so the parameter defaults of `def assert_equal(a:
object, b: object, fmt: str = "{} != {}")` are no assignment, while a call of it still reports.

A field initializer inside an anonymous or typed literal is not a mutation: Zig `.{ .value = 1 }`
and `Value{ .key = 2, .value = 2 }`. A binding that a block inside the assertion declares is not one
either, Rust `assert_eq!(x, { let m = cap.get(0).unwrap(); m.start() })` or Zig `const held = g();`
in a labelled block, since the name ends with the block; its initializer is still read, so `let held
= queue.pop();` reports for `pop`. A dotted target anywhere else is: `values.length = 0`, `s.count
+= 1`, and Rust `{ s.count = 1; true }` each report. A comparison, `===` and `!==` included, is not
an assignment, and a named argument, `f(name=value)` where the language spells arguments that way,
Python's `assert helper(count=1)` and Odin's `assert(len(items) > 0, loc=loc)`, is not one either.
Rust spells a named argument only inside a macro invocation, so a `name = value` argument of a macro
nested in the assertion, `format!("{x}", x = value)` or a test macro's `current_dir = path`, is that
macro's own syntax and is quiet. A `name = value` in the assertion's own arguments that follows the
values it checks, one for `assert!` and two for a name ending in `_eq`, `_ne`, or `_matches`, is the
macro's named option or format argument and is quiet too, `assert_relative_eq!(a, b, epsilon =
1e-6)` and `assert!(ready, "{name}", name = label)`; one in the checked position,
`debug_assert!(count = 1)` or `assert_eq!(a, b = 1)`, still reports. A Go channel receive `<-ch` and
an `await` inside an assertion report, since each one advances a program the assertion is meant to
observe. A call reports when it names a mutating method or function of the language: Go `Add`,
`Close`, `Delete`, `Lock`, `Pop`, `Push`, `Remove`, `Reset`, `Set`, `Store`, `Unlock`, `Write`,
`append`, `close`, and `delete`; JavaScript `add`, `assign`, `clear`, `copyWithin`, `delete`,
`fill`, `next`, `pop`, `push`, `remove`, `reverse`, `set`, `shift`, `sort`, `splice`, and `unshift`;
Python `__delitem__`, `__setitem__`, `acquire`, `add`, `append`, `clear`, `discard`, `extend`,
`insert`, `next`, `pop`, `popitem`, `popleft`, `print`, `read`, `remove`, `reverse`, `send`,
`setdefault`, `sort`, `update`, and `write`; Rust `append`, `clear`, `drain`, `extend`, `insert`,
`lock`, `next`, `pop`, `push`, `push_str`, `remove`, `remove_file`, `replace`, `reserve`, `retain`,
`sort`, `swap`, `take`, `truncate`, `write`, and `write_all`; Zig `append`, `appendSlice`,
`clearRetainingCapacity`, `insert`, `next`, `orderedRemove`, `pop`, `popOrNull`, `put`, `remove`,
`reset`, `resize`, `set`, `swapRemove`, `write`, and `writeAll`; Odin `append`, `append_elem`,
`append_elems`, `append_string`, `clear`, `delete_key`, `inject_at`, `ordered_remove`, `pop`,
`pop_front`, `push`, `remove_range`, `reserve`, `resize`, `shrink`, `unordered_remove`, `write`, and
`write_string`. A Python method is called through its receiver, so a bare call of a listed name
other than the builtin functions `next` and `print`, `reverse("admin:login")` under `from
django.urls import reverse`, calls a function of the file's own and is no mutation, while
`values.reverse()` still reports. A call whose receiver is a name the file binds with `import`,
`np.sort(arr)` or `np.add(a, b)` under `import numpy as np`, calls a module's function rather than a
method of a value, while a member reached through the module, `flask.g.pop("bar")`, still reports. A
Rust call of a listed name is no mutation when each function of that name the file declares takes
`&self`, as a `ReadStrategy::next(&self) -> usize` getter does; with no declaration in the file, or
one taking `&mut self`, it reports.

A mutation inside a function literal the assertion passes as an argument is exempt when the
callee stores the function for later, since the assertion does not run it; a callback
handed to `all`, `any`, `every`, `filter`, `find`, `forEach`, `map`, `reduce`, or `some`
runs before the assertion returns, so a mutation inside it reports.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS036, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `node-shape-anchor` and `macro-token-tree`.

## Citations
