# TS044 member-order

The severity is info; the rule is opt-in by default and stable.

## Reports

A type is ordered fields, then nested types, then methods, so its shape reads before its
behaviour.

Reporting unit: Each container, and a container reports the first out-of-order member and stops.

Anchor: The offending member.

Carve-outs: The containers are per language. Zig reads `struct`, `enum`, `union`, and
`opaque` containers, including the `const S = struct {`, `return struct {`, and `try struct
{` spellings. Rust reads `impl` and `trait` bodies only, because a Rust `struct` body is
fields alone and its methods live elsewhere. JavaScript reads `class` bodies, TypeScript
`class` and `interface` bodies, and Python `class` bodies. Go and Odin are off: a Go struct
holds only fields, and its methods are declared outside it, so the order is not the author's
to choose.

A member ranks by its leading word, past up to four modifiers, where a ranking word is read
before a modifier is skipped, so Rust's `type Item = u32;` ranks by `type`: Rust reads
`const` as a field and `type` as a nested type, Zig reads `const` and `var` as nested types
and labels one whose value is not a container and whose name is not title case a constant,
Python reads a nested `class` as a nested type, and a function is a method everywhere. A
member that carries no leading word is a field when it opens with a name followed by `:`,
`=`, or `,`, which is how Zig spells a container field and a union tag and how a TypeScript
interface spells a property. A qualified path, a name followed by `::`, is not a field, so a
Rust macro invocation inside an `impl` body ranks as nothing and is skipped.

A Python class-body binding whose value is the bare name of a method the class declares above it,
`config = configure` or `__ror__ = __or__`, is a second name for that method and ranks as a method
rather than a field, and so is a chain, `__eq__ = __ne__ = raises_anything`, while `limit =
configure_limit` is a field.

## Does not report

The rule reaches JavaScript, Python, Rust, TypeScript, and Zig. A Go struct holds only
fields; its methods are declared outside it, so the order is not the author's to choose.
An Odin struct holds only fields; its procedures are declared beside it, so the order is
not the author's to choose.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS044, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `python-class-field`, `anonymous-container-scope`, and `inline-struct-field-order`.
