# TS014 no-nested-functions

The severity is warning; the rule is opt-in by default and stable.

## Reports

A function is declared at the top level rather than inside another function, so the call
graph stays flat.

Reporting unit: Each nested function. A JavaScript or TypeScript arrow function bound to a
name inside a function, `const inner = () => {}` or `inner = (x) => x`, is a nested
function and reports here; a lambda a keyword introduces, whether bound to a name or not
(`function () {}`, `func() {}`, `lambda:`, `|x|`), is TS015's and is not repeated here.

Anchor: The first token of the line the nested function's header opens on; for a bound arrow
function, the bound name.

Carve-outs: A declaration with no body, such as a Rust trait method signature, is not a nested function.
Zig exempts the inner functions of a function that returns `type`, because such a function is
a namespace and its members are top-level in every sense that matters. Both tests are shared
with TS002's namespace carve-out. A language whose types are values, which
`types_are_values` names and which is Odin and Zig, exempts a function whose immediate
parent is a container as well: Zig's `const held = struct { fn make() ... };` and the
`struct { fn continuation(...) ... }` passed as a callback declare members of a type, which
is how the language passes a function at all, and the same namespace argument covers them.
A function that is not a declaration is not nested either: a function passed as an argument,
an object-literal method, an object-literal property whose value is an arrow function, a
class method, and the function an immediately invoked or UMD wrapper calls at module level
are each something else, and the last is the module itself. A named function declared
inside an arrow function or a callback counts, because the arrow is a function too. Where
nested functions can be closures, which is JavaScript, Python, and TypeScript, a nested
function the enclosing function returns by name, and a Python nested function under a
decorator, however many lines the decorator's arguments span, are closures rather than helpers and
are exempt.

A fixture file is exempt: one under a snapshot or `testdata` directory, or one under a `test`,
`tests`, `__tests__`, or `spec` directory that holds no test of its own, which is a formatter
or highlighter input rather than a test. A file holds a test when it carries `#[test]`,
`cfg(test)`, or `@(test)`, a `test` block, a function whose name opens with `test`, `Test`,
`bench`, or `Benchmark`, or a callback handed to `test`, `it`, `describe`, or `bench`.

## Does not report

The rule reaches JavaScript, Odin, Python, Rust, and TypeScript. Go has no nested named
function; a func literal is a lambda, which TS015 reports. Zig has no nested function
either: a `fn` is legal only at container scope, so each inner function is a member of a
`struct` and the container carve-out exempts all of them.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS014, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `nested-closure`, `container-member`, `inherited-type-level`, and `python-nested-function`.
