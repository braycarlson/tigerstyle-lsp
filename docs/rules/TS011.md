# TS011 no-star-import

The severity is warning; the rule is on by default and stable.

## Reports

An import names what it brings in, so a reader can tell where a name came from.

Reporting unit: Each wildcard. An import that opens two paths with `*` reports twice.

Anchor: The single token after the import keyword, which is the head of the path the statement brings in; Python anchors at the `*`.

Carve-outs: An import reports wherever it stands: at module level, inside a function, under an
attribute, and behind a visibility, so `pub use x::*` and `pub(crate) use std::fmt::*` report,
since a re-export brings each name into scope for the reader of the re-exporting module just
as a plain `use` does, and nothing in the standard licenses a wildcard inside a function.

There is one exemption, and it rests on a language fact. A Rust `use super::*` directly inside a
`mod` that carries `#[cfg(test)]` on the line above is quiet, because a test module is the parent
module's own file scope re-entered, and the names it reaches are the ones the reader already has in
view. The same path anywhere else reports, and so does `use self::*`.

An aliased namespace import, `import * as name`, is exempt, because the alias is the name the
reader follows.

## Does not report

The rule reaches Go, JavaScript, Python, Rust, and TypeScript. Odin has no wildcard
import; an import binds one package name. Zig has no wildcard import; @import binds one
name.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS011, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.
