# TS045 no-alias

The severity is info; the rule is opt-in by default and stable.

## Reports

A binding that renames another value gives one thing two names, which can disagree.

Reporting unit: Each declaration.

Anchor: The bound value.

Carve-outs: The rule runs inside a function only, and a member of a container declared inside one is
not a local. The value is a single name, or JavaScript's `this`, so `const self = this` and `const
that = this` report. A binding is exempt when the alias itself is assigned again later in the
enclosing function body, by `=`, a compound assignment, or `++`/`--`: `m := value; m += 1` declares
a new variable that started from `value` rather than a second name for it. The assignment counts as
one target of a tuple, `p, _ = replace(p)` or `if path, err = abs(config_path)`, and inside a block
nested in the alias's own, `cap_end += 1` in a loop body; it does not count once the alias's block
has closed, nor as a `:=` that declares a fresh name, so `err := limit` inside an `if` still reports
beside a later `result, err := other()`. A Zig `var` is that new variable by construction: Zig
rejects a `var` the function never mutates, and Zig parameters are constants, so `var rest =
iterator;` before `rest.next()` and `var limits = limits_test;` before `limits.depth_max = 2;` are
the only way to mutate a copy, and neither reports. A Zig `const` that freezes a `var` inside a
`comptime` block, `const kebab = buffer;` before `return &kebab;`, is the language's requirement
too, since a pointer to a comptime `var` cannot leave the block. The same holds wherever the frozen
copy's address or slice is itself the value of a `return`, a `break`, or an assignment, `const final
= buf;` before `break :numeric final[0..len :0];`: a runtime copy could not lend its bytes past its
block, so the code runs at compile time, as a function building a table for `initComptime` does. A
frozen copy whose address is only handed to a call, `use(&held)`, is still an alias. A source that
is later assigned, has its address taken, or is mutated through a method is exactly the
desynchronisation the standard names, so `copied := value; value = 5; return copied` and `copied :=
value; p := &value; *p = 5` report; outside a Zig `var`, a method call on the alias is no exemption
either. A re-binding of a name already bound in an enclosing scope is an update rather than a
declaration, and a name a parameter already binds is the same. A value the enclosing header binds is
not aliased either, which covers a loop variable captured for a closure and an exception bound by an
`except` or a `catch`; only the header is read, never the statements before the binding in a Python
block, so `x = copy` after `copy = value` and `b = a` after `a = self.a` report as they do in Rust.
A value that is a type name is not an alias but a type alias, and is exempt: the primitive names per
language, Rust's seventeen and Zig's builtin set including each `uN` and `iN`, and a title-case name
bound to a title-case value. A value that is a constant name is exempt by screaming case. A literal
constant, `true`, `false`, `nil`, `null`, `None`, `True`, `False`, or Zig's `undefined`, is a value
rather than a name. A value followed by a block, as in `let config = Config {`, is a literal whose
head tigerstyle-lsp's syntax pass records alone, and is not an alias. A comment trailing the value
does not make it a two-token value.

A Python name the function declares `nonlocal` or `global` is the enclosing scope's binding, so
`seen_headers = response_headers` under `nonlocal seen_headers` updates that binding rather than
naming the value twice.

A three-clause loop header's induction variable, `for idx := sidx; idx < eidx; idx++`, is not
an alias of `sidx`, since a counter the loop moves is not a second name for the value it
started at. A discard, Odin's `_ = held` or Go's `var _ CompletionFunc = userComp`, binds
nothing, so the name a language spells as its discard is not an alias.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS045, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `type-as-alias`, `loop-induction-binding`, `container-member-alias`, `pattern-destructure`, and `blank-identifier-binding`.
