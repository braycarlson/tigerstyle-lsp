# TS034 callback-last

The severity is warning; the rule is opt-in by default and stable.

## Reports

A callback parameter comes last, because it is the one the function invokes.

Reporting unit: Each function, in a declaration, an anonymous function expression, or a
lambda bound to a name, and a function reports the first callback that precedes another
parameter.

Anchor: The offending parameter.

Carve-outs: A function whose last parameter is itself a callback is exempt. A parameter is a
callback when any of four tests holds. Its type text carries a marker outside a slice or an array,
so `list: &[fn(&str) -> u32]` holds callbacks rather than being one: Rust `Fn(`, `FnMut(`,
`FnOnce(`, `dyn Fn`, `impl Fn`, and `fn(`; Go `func(`; Odin `proc(`; Zig `fn (`; Python `Awaitable`,
`Callable`, and `Coroutine`; JavaScript and TypeScript `=>`, `function(`, and `Function`. A marker
spelled as a word matches only a whole word, so mypy's own class `CallableType` carries no
`Callable` and `FunctionComponent` no `Function`, while `typing.Callable[[int], None]` carries one.
Its type is a type parameter the signature bounds by a marker, `fn run<F: Fn(u32)>(handler: F)` or
`where F: FnMut(u32)`, or a TypeScript `F extends (v: number) => void`. Its type is a same-file
alias whose right side carries a marker: Go `type Handler func(int)`, TypeScript `type Handler = (v:
number) => void`, Odin `Handler :: proc(int)`, and Python `Handler = Callable[[int], None]`; a class
or struct whose body happens to mention a callable is not an alias, since the marker is read only
before the declaration's body, its first `{` or a Python class's indented suite, so a struct, union,
or enum that holds a function pointer, even a `union(enum)` of them, is a type rather than an alias,
and so is a Python class whose methods take a `Callable` parameter. Its default is a function or a
lambda, or the body invokes it by name as `name(`, which is how an untyped JavaScript or Python
parameter shows itself to be a callback; `new Name(` constructs and does not count, and neither does
the call of a Python parameter annotated as a class, `parser_type: type[Any]` before
`parser_type(*params, stream)`, which constructs the class rather than calling back. A Python
parameter whose name says it holds a class constructs it the same way: a title-case name, `def
build_instance(Model, data, db)` before `Model(**data)`, since Python spells a class in title case,
and a name ending in `class`, `klass`, or `_cls`, as `migration_class` and `klass` do.

A parameter with a default, a TypeScript optional `name?`, and a variadic parameter are not
required, so a callback followed only by those is last in each call. A method's receiver, `self` in
Rust and Python, is never the callback: the language fixes it first, so `fn build(&self, app: &mut
App) { self(app); }` in an `impl` for a closure type has no order that would put it last, while a
callback parameter after the receiver, `fn run(&self, handler: impl Fn(u32), name: &str)`, still
reports. A Python class method's receiver, `cls`, is never the callback either: `return cls(config)`
constructs the method's own class. A `comptime` parameter is not a callback, and neither is a
parameter whose type is a type, Odin's `$T: typeid`, whose `T(a)` converts a value rather than
calling back. A call through a member, `t.procedure(t)` or the package function `linux.futex(futex,
expected)`, does not invoke the parameter that shares its name. The parameter the callback receives
as its own context, paired to it by type, is exempt, because TigerBeetle's own signatures write the
pair that way: `Journal.write_prepare(journal: *Journal, callback: *const fn (journal: *Replica,
wrote: ?*Message.Prepare) void, message: *Message.Prepare)` puts the message the callback will be
handed after the callback, and the rule follows the style's own reference code there. A signature on
a foreign boundary is dictated by the other side and is exempt: a function whose own head or tail
carries a boundary marker, Zig `export`, `extern`, or its own `callconv`, Rust `extern`, Odin
`foreign`, or Go `Call` or `Syscall`, as in `export fn wl_proxy_add_listener(proxy, implementation,
data)`, whose order the C header fixes. A function declared inside a block whose opening line begins
with a marker is on the same boundary: a Rust `extern "C" {` or `unsafe extern "C" {` block and an
Odin `foreign lib {` block declare what the other side defines, so `fn emscripten_async_call(func:
extern "C" fn(*mut c_void), arg: *mut c_void, millis: i32);` keeps Emscripten's order. A Zig `extern
struct` or `opaque` container opens on its binding, `const Proxy = opaque {`, rather than on a
marker, so its methods are the file's own. A marker inside a parameter's type, `callback: *const fn
() callconv(.c) void`, belongs to the callback rather than to the function and exempts nothing.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS034, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.

## Citations

TigerStyle: "Callbacks go last in the list of parameters. This mirrors control flow:
callbacks are also _invoked_ last."
