# TS041 simple-return-type

The severity is warning; the rule is on by default and stable.

## Reports

A return type carries one layer of optionality, because each layer is a case each caller has
to handle.

Reporting unit: Each function.

Anchor: The return type.

Carve-outs: The rule counts the optional layers stacked along one path of the return type and
reports at two or more. The standard ranks `?u64` above `!u64` and asks for fewer dimensions, so
two layers report whether they are the same wrapper or different ones: `Option<Option<T>>`,
`Result<Option<T>, E>`, `Option<Result<T, E>>`, Zig `??T`, `!?T`, and `anyerror!?T`, Python
`Optional[Optional[int]]`, `Optional[int] | None`, and `Optional[Union[int, None]]`, and Odin
`Maybe(Maybe(int))`. The markers are Rust `Option<` and `Result<`, Zig `!` and `?`, Python `None`
and `Optional[`, which are one marker, Odin `Maybe(`, and TypeScript `null` and `undefined`, each
matched as a whole word, so `Nullable<T>` holds no marker.

A container starts a new path. A generic or a bracket that is not itself a marker, `Vec<`, `Box<`,
`HashMap<`, `[`, `list[`, `dict[`, `tuple[`, `set[`, and `struct {`, resets the count for what
it holds, so `Option<Vec<Option<u32>>>`, `Optional[list[Optional[int]]]`, `Maybe([]Maybe(int))`,
and Zig `?struct { a: ?u32 }` are one layer each: an element's optionality is a case the caller
meets once it has the collection, not a branch on the return itself. A tuple is not a container
in that sense, since destructuring it hands the caller each member at once, so `(` carries the
count rather than resetting it and `Option<(String, Option<String>)>` reports two layers while
`Option<(u32, u32)>` reports one. A Zig array or slice prefix, `[]` or `[N]`, is
followed by its element type, which is a new path too, so `?[]?u32` is one layer. `Promise<` and
`Union[` are transparent: what they hold stays on the same path.

Go and Odin return a list of results, and the rule counts its optional dimensions. A trailing result
typed `bool` or `error` in Go, `bool` or an `Error` type in Odin, is one layer each, on top of
whatever the first result carries: in Odin its `Maybe(` markers; in Go a first result that can be
`nil` and whose `nil` a caller must branch on, a pointer `*T`, a `func`, an `interface`, `any`, or a
`chan`. That count reports `(*T, error)`, `(int, bool, error)`, and `(Maybe(int), Error)`, while
`(int, error)`, `(bool, error)`, and `(int, bool)` are one layer. A Go slice or map result is not a
layer, because a nil slice or map reads as empty and a caller writes no branch for it.

TypeScript's union is counted by its absent members: `number | null | undefined` has two, `=== null`
and `=== undefined`, and reports, inside `Promise<...>` as well; `number | null` has one.

## Does not report

The rule reaches Go, Odin, Python, Rust, TypeScript, and Zig. JavaScript declares no return
type, so there is nothing to count.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS041, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

`Result<T, Option<E>>` reports, since the error path stacks two wrappers, though the value path
carries one.

## Citations

TigerStyle: "Use simpler function signatures and return types to reduce dimensionality at
the call site, the number of branches that need to be handled at the call site, because
this dimensionality can also be viral, propagating through the call chain. For example, as
a return type, `void` trumps `bool`, `bool` trumps `u64`, `u64` trumps `?u64`, and `?u64`
trumps `!u64`."
