# TS038 positive-invariants

The severity is info; the rule is on by default and stable.

## Reports

A branch carrying an `else` states its condition positively, so the reader meets the expected
case first.

Reporting unit: Each branch.

Anchor: The negation, or the inverted comparison operator.

Carve-outs: A condition is negative when it opens with `!` or `not`, or when its comparison
at the condition's own depth is an inverted form: `!=`, `!==`, Python `not in` and `is not`,
Odin `not_in`, and `>=` or `<=` when the condition names a length (`len`, `length`, `count`,
`size`, `capacity`), since a bound compared the other way round is only a negation where one
side measures the other, as in the standard's own counter-example `if (index >= length) {}
else {}`, which reports; `if (a <= b) {} else {}` is a positive comparison and is quiet.

The `else` requirement is a deliberate reading. A guard such as `if !ready { return }`
handles the negative space on its own and has no arms to swap, and the standard's
counter-example carries an `else`; only then does putting the positive case first change
what the reader meets. A branch whose alternative continues a chain is exempt, since the
arms are cases rather than a positive and its negation. A condition that reaches past the
negation, with an `and` or an `or` in it, is exempt because the positive form is not a
text edit.

A `!` that closes a macro name, as in Rust's `matches!(x, Some(_))`, is a call and not a
negation; the check is made only where the language invokes macros with `!` and only when
an identifier touches the `!`, so `if !(a)` is a negation in each language.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS038, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `go-negated-conjunct` and `zig-else-clause`.
