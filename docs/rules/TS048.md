# TS048 main-first

The severity is info; the rule is opt-in by default and stable.

## Reports

The entry point comes first in the file, so a reader meets the top of the call graph before
its parts.

Reporting unit: Each file.

Anchor: The name of `main`.

Carve-outs: A function counts only at the top level, where a function is a declaration or a lambda
bound to a name, so `const main = () => {}` is `main` and a `const helper = () => {}` above
it is another function. A function inside a module or namespace body, a Rust `mod w { }` or
`extern` block or a TypeScript `namespace` or `declare module`, is not top level; one that a
top-level branch declares, under Python `if X:` or Odin `when`, still is. The first `main` alone
reports. A file with no `main` is quiet.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS048, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.

## Citations

TigerStyle: "_Order_ matters for readability (even if it doesn't affect semantics). On the
first read, a file is read top-down, so put important things near the top. The `main`
function goes first."
