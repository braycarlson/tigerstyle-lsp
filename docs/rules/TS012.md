# TS012 line-too-long

The severity is warning; the rule is on by default and stable.

## Reports

A line fits in 100 columns, so two files sit side by side without wrapping.

Reporting unit: Each line.

Anchor: The span from the first column past the limit to the end of the line, or the widest
token when that token alone exceeds the limit.

Carve-outs: A column is one character, and a tab advances to the next tab stop of four, so a
Go line indented with two tabs starts at column eight. A line holding a token that cannot fit
under the limit reports like any other, since the standard admits no exception; the finding
sits on that token and says whether it stands alone or should be moved to a line of its own. A
line opening with a per-language exempt prefix is exempt, which is Zig's multiline-string `\\`
marker: splitting such a line changes the string's contents, so the only remedy is to change
the string.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS012, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shape that misfires here is `dot-directory-walked`.

## Citations

TigerStyle: "Hard limit all line lengths, without exception, to at most 100 columns for a
good typographic 'measure'. Use it up. Never go beyond. [...] just enough to fit two
copies of the code side-by-side on a screen."
