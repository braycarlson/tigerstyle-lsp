# TS025 big-endian-names

The severity is info; the rule is on by default and stable.

## Reports

A name is ordered from most significant word to least, so related names sort and read
together.

Reporting unit: Each name, at most once, the leading test first.

Anchor: The name token.

Carve-outs: The name corpus takes in each declared value, field, parameter, and function name; a
type name is left to TS042. A name is split into words on underscores and camel boundaries, so
`maxSize`, `numItems`, `MaxRetries`, and `MAX_SIZE` are read the same way as `max_size`. A qualifier
is one of three tiers: a measure (`count`, `index`, `len`, `length`, `n`, `offset`, `size`), a unit
(`bytes`, `ms`, `ns`, `us`), or a bound (`average`, `avg`, `cur`, `current`, `first`, `initial`,
`last`, `max`, `maximum`, `mean`, `min`, `minimum`, `new`, `next`, `num`, `old`, `previous`, `sum`,
`total`). A name of two or more words whose first word is a qualifier reports as leading with it,
except that `index`, `offset`, and `size` name a quantity of their own and may lead, so `size_max`
and `index_first` pass while `count_items`, `n_items`, `first_index`, and `sum_total` report. A
function name may lead with `average`, `count`, `sum`, or `total`, which read as verbs there. The
qualifiers past the first word must run measure, then unit, then bound, so `latency_max_ms` and
`buffer_max_size` report while `latency_ms_max` and `size_bytes_max` pass. A first word followed
only by qualifiers of a later tier is the subject of the name, so `count_max` and `bytes_max` pass
while `bytes_count` and `max_count` report. A single-word name never reports.

A name opening with an underscore is skipped. A parameter whose name spells its own declared
type is exempt from the leading test, as in `next_tick: *Grid.NextTick`, and the test runs where the
parameter carries a `Type` node. Rust exempts a field of a type carrying a serde attribute,
because the name is an external contract. JavaScript and TypeScript class members and
object-literal keys are names, as is a Python `self.` or `cls.` attribute at its first
assignment in the file.

A Python stub, a `.pyi` file, restates a module the runtime defines, so a name it declares is the
runtime's spelling, fixed by that module as an `extern fn` name is by the linker, and is exempt:
`def getLevelName(level)` in `logging/__init__.pyi` and the keyword parameter `opt_str` of
`optparse.pyi` name what CPython names. A parameter before the `/` is positional only, a name no
caller spells, so it stays the stub's own and reports, and so does a declaration the stub marks
`@type_check_only`, which exists for the type checker alone.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS025, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shape that misfires here is `destructure-single-name`. An English compound whose first
word is a qualifier, such as `first_name` or `new_york`, reports, because the standard gives
no exception and the linter cannot tell a qualifier from a proper noun.

## Citations

TigerStyle: "Add units or qualifiers to variable names, and put the units or qualifiers
last, sorted by descending significance, so that the variable starts with the most
significant word, and ends with the least significant word. For example, `latency_ms_max`
rather than `max_latency_ms`."
