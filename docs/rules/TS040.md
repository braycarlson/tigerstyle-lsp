# TS040 division-intent

The severity is info; the rule is opt-in by default and stable.

## Reports

An integer division discards a remainder silently, so the code says which way it rounds. An
integer remainder takes its sign from one operand, so the code says which.

Reporting unit: Each `/` or `%` operator.

Anchor: The division expression.

Carve-outs: An operand is a float when it is a number literal with a `.`, an exponent, or an
`f32`/`f64` suffix, a float type name such as `f32` or `f64` as in `x as f64` or `@as(f64, x)`, a
builtin whose name starts with `@float`, or a single name whose declaration in the enclosing
function reads `name: fN`. A member operand whose receiver's type the file declares takes that
type's field: `group.height` with `group: Size`, a local `var group: Size`, or `self.height` inside
`Size`, reads the `height` that `Size` declares, and so does a type the file qualifies by its own
name, `group: Glyph.Size` under `const Glyph = @This();`, and so does a parameter typed by an inline
struct, `v.far` with `v: struct { near: f32, far: f32 }`, which reads the field that struct spells.
A member operand whose receiver cannot be resolved, `size.height` or `bounds.width()`, is a float
when each field of that name the file's named containers declare has a float type, `height: f64`,
or each function of that name returns `f64`. A field declared with a float type in one container
and an integer type in another is not a float, and a local or a parameter spelled like the member is
not a field and decides nothing. A float on either side exempts the site. An identifier chain such
as `self.count / self.width` is not a float.

Zig reads every other operand as an integer, since the language has no implicit numeric conversion
and its integer types are explicit. A Rust site reports only on integer evidence: an
integer literal on either side, a `.len()`, `.len`, or `.count()` on either side, an
integer type name such as `u64` on either side as in `x as u64 / y as u64`, or both
operands being single names declared `name: iN` or `name: uN` in the enclosing function. A
Rust site without such evidence is quiet, since a name whose type is inferred cannot be
read. The evidence is read at the operand's own level: a literal or a length inside an index or a
call's arguments, `t[3]` or `display_scale(channel.0)`, says nothing about the value the operand
yields, and a number after a member dot, `ui_scale.0`, is a tuple field rather than a literal. A
right operand followed by a cast to a float type, `(end - start) / (count + 1) as f32`, is a float,
since `as` binds tighter than `/`.

A `/` whose divisor is a power-of-two literal is exempt only when the left operand is a
single name declared unsigned, because a shift floors while a signed `/` truncates. A `%`
reports only when its left operand is a single name declared signed, because `@rem` and
`@mod` agree on an unsigned value and a value of unknown signedness cannot be judged; Zig
rejects `%` on a signed operand at compile time, so in Zig the finding names code that
does not build. A name declared signed that a Rust `let` rebinds before the use, `let total =
total.unsigned_abs();` above `total % 60`, no longer holds the declared sign, so its signedness
is unknown; a rebinding inside a block that closes before the use, or one whose own initializer
holds the use, leaves the declaration in force.

## Does not report

The rule reaches Rust and Zig. Go, JavaScript, Odin, Python, and TypeScript spell integer
division with the same operator as float division and convert implicitly or dynamically,
so telling them apart needs type inference this linter does not do; Python's `//` already
names the rounding.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS040, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

A Zig field or call whose float type is declared in another file, such as `vec.x /
vec.len()` over an imported `Vec`, reports, since only the file's own declarations are read.

The shapes that misfire here are `chained-division` and `node-shape-anchor`.
