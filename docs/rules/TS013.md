# TS013 no-global-statement

The severity is warning; the rule is on by default and stable.

## Reports

A function does not rebind module state, so its effects stay in its return value.

Reporting unit: Each statement.

Anchor: The `global` keyword in Python; the host name in JavaScript and TypeScript.

Carve-outs: Each `global` statement reports, inside a test as anywhere else, since no standard
exempts a test from the scope rule. A `nonlocal` statement does not report. Its name resolves
only to a binding of an enclosing function, and Python rejects the statement at module level or
where no enclosing function binds the name, so it rebinds that function's local and never
module state. The variable keeps the enclosing function's scope, which is the smallest scope
the two functions share. A callback that counts its own calls through `nonlocal count` inside a
test is that shape.

JavaScript and TypeScript have no keyword, so the rule reads the shape that does the same
work: an assignment, plain or compound, to a member of `globalThis`, `window`, or `global`
inside a function, such as `globalThis.count = 1` or `window.held += 2`, rebinds global state
by name and reports at the host. The same assignment at module level is a declaration and is
TS005's concern. `self` is not a host here, because `self` inside a function is more often
a captured `this` than the worker global.

A host a function receives as a parameter reports the same way. The factory of a UMD module
such as jQuery's, `function( window, noGlobal ) { ... }`, is handed the global object, so
`window.jQuery = jQuery` inside it still creates a global, which P10 Rule 6 and TigerStyle's
smallest-scope rule both forbid.

## Does not report

The rule reaches JavaScript, Python, and TypeScript. Odin, Rust, and Zig have no global
statement; a binding never reaches out of its scope by keyword. Go has no global statement
either; a function that writes a package variable, `counter++`, is caught where the variable
is declared, since TS005 reports each package-level `var`.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS013, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.

## Citations
