# TS020 no-warning-suppression

The severity is warning; the rule is on by default and stable.

## Reports

A warning is fixed rather than silenced, because the next reader cannot tell a silenced
warning from a checked one.

Reporting unit: Each line, and a line reports only the first marker it carries.

Anchor: The marker text.

Carve-outs: The watched attributes are `allow`, `cfg_attr`, and `expect`, each under a `#[` or `#![`
marker. A `cfg_attr` head fires only when the line also carries `allow(` or `expect(`, since a
conditional attribute that derives or configures silences nothing. The watched comment markers come
from each language's conventions table: Go `lint:ignore`, `nolint`, and `nosec`; JavaScript and
TypeScript `biome-ignore`, `eslint-disable`, `ts-expect-error`, `ts-ignore`, `ts-nocheck`, and
`tslint:disable`; Python `mypy: ignore-errors`, `noinspection`, `noqa`, `nosec`, `pylint: disable`,
`pyright: ignore`, and `type: ignore` with or without the space; Odin `#no_bounds_check` and
`odinfmt: disable`; and Zig `lint:file-ignore`. A comment marker counts where it opens a directive:
right after the comment's opener (`#`, `//`, `/*`, or a `@` as in `// @ts-ignore`) or after another
opener that whitespace sets apart, as in `# noqa: E501 # type: ignore`; a marker quoted inside
prose, `# Warn about unused '# type: ignore' comments`, silences nothing. There are two builtins
that are suppressions by declaration: Odin's `#no_bounds_check`, and Zig's `@setRuntimeSafety` when
its argument is `false`, since `@setRuntimeSafety(true)` silences nothing. Python's
`warnings.filterwarnings` and `warnings.simplefilter` report when an argument is the string
`"ignore"`, because the call silences the interpreter's own checker at runtime. A directive that
follows prose in the same comment, `# 0xFF13: ３ Em 3  # noqa: RUF003`, is reported from its own
opener, and the fix deletes the directive alone and keeps the prose.

Nothing exempts a suppression once it is one. A comment on the same line, a comment on the
line above, and a Rust `#[expect(...)]` that names only tool lints and carries a `reason` all
report, because the standard admits zero warnings rather than justified ones, and a
suppression whose reason is written down is still a warning the compiler no longer prints.
Go's `//go:nosplit` is a stack-growth directive rather than a suppression and is not watched.

A `# noqa: F401` on an import under a `TYPE_CHECKING` block stays quiet, because the import is
used by the type checker the block exists for, so the warning it silences is not a warning.

The unsafe fix deletes the suppression whole and nothing past it: a comment, an attribute through
the `]` that closes it however many lines it spans, Odin's `#no_bounds_check` directive, and a
`@setRuntimeSafety(false)` or warnings-filter call through its closing parenthesis and a `;` that
ends it. The code that shares a line with the suppression stays, so `struct
Marker(#[allow(dead_code)] *mut ());` keeps its field, and a line the suppression filled is left
empty. A Python warnings filter that is the only statement of its block becomes `pass`, and one that
is no whole statement, the value of an assignment or a suite written after its colon, reports
without a fix.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS020, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `type-only-import-suppression`, `adapter-coverage`, and `marker-inside-a-comment`.
