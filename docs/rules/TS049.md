# TS049 trivial-assert

The severity is warning; the rule is opt-in by default and stable.

## Reports

An assertion that cannot fail checks nothing, and one that cannot hold checks nothing
either.

Reporting unit: Each assertion.

Anchor: The condition span.

Carve-outs: The condition is the assertion's condition argument: the first argument, cut
at the first comma the parentheses do not hold, so a message after it does not hide the
condition; for a Go testify helper the argument after `t`; for Python's parenless statement
the text up to the first comma, with outer parenthesis pairs peeled. A macro assertion is
cut the same way, so `assert!(true, "unreachable")` reports. A number after the condition
is no message, so a call that passes one is a helper whose first parameter is something
other than a condition, and it is quiet: a Go test's own `assert(1, 5, 15, colour)` passes
an index first, while `assert(1, "unreachable")` still reports.

A helper that takes a condition is `assert`, `debug_assert`, `expect`, `ok`, `True`, `False`,
`assertTrue`, and `assertFalse`, however the receiver spells it. A literal `true`, `True`, or `1`
handed to one of those reports as never failing, as does Python's `not False`, a non-empty string
literal, and a non-empty list or tuple literal; a literal `false`, `False`, `0`, or `not True`
reports as never holding. A never-holding assertion on a path that must not run reports too, because
P10 Rule 5 names an assertion that can never hold as well as one that can never fail. The path is
marked with the language's own construct instead: Zig `unreachable`, Rust `unreachable!()`, a raise
in Python, or `assert.fail()` in Node. TigerBeetle writes `unreachable` 564 times and
`assert(false)` twice.

A tautology reports: the condition text is split on the first of `===`, `!==`, `==`, `!=`,
`>=`, `<=`, `>`, `<`, ` is not `, or ` is `, in that order, and reports when the trimmed sides
match, so `x > x` and `x is not x` report along with `x == x`. A helper that compares two
values, one whose name carries `Equal`, `equal`, `Same`, `_eq`, `_ne`, or `assertIs`, is not a
condition helper: its first argument is a value rather than a condition, so
`expectEqual(true, ready(value))` is quiet, and it reports only when its two arguments are the
same text, as in `assert_eq!(x, x)`, `expectEqual(x, x)`, and `assertEqual(x, x)`. Any other
helper, such as `Nil`, `Len`, or `throws`, is not read. A call chained after the helper, as in
`expect(true).toBe(x)`, is a matcher rather than an assertion of its argument and is quiet,
unless the matcher is handed the same term the helper was: `expect(true).toBe(true)` and
`expect(value).toBe(value)` cannot fail, which is the padding the rule's own citation names,
while `expect(parse(x)).toBe(true)` can and does not report. Zig `unreachable` is skipped,
because it carries no parentheses and Zig does not spell an assertion without them.

A condition whose left side holds a call is exempt, since `f() == f()` can answer differently
each time. A file that implements a comparison of its own, a Rust `impl PartialEq`, `Eq`,
`PartialOrd`, or `Ord` for a type with its `for` on the `impl` line, or a Python `__eq__`,
`__ne__`, `__lt__`, `__le__`, `__gt__`, or `__ge__` method, tests that comparison when it compares a
term with itself: under `impl PartialEq for FloatOrd`, whose `eq` holds NaN equal to NaN,
`assert_eq!(NAN, NAN)` checks a property a plain float comparison fails, so a self comparison in
such a file is quiet. A derived comparison is the compiler's and leaves the tautology reported,
and a literal reports whatever the file implements.

Python runs the object's own code to compare it, so two more Python shapes are quiet. A term that
reads an attribute or a subscript runs a property, a descriptor, or `__getitem__` on each read, so
`self.assertIs(charlink.content_object, charlink.content_object)` tests that the descriptor caches
its object, as a call would. A name the function binds from a call, `constraint =
UniqueConstraint(...)` before `self.assertEqual(constraint, constraint)`, holds an object whose
class may implement `__eq__` in any module, so its self comparison through equality or ordering
tests that method. An identity comparison of a bare name, `assertIs(x, x)` or `x is x`, cannot
dispatch and still reports, as do a literal, a parameter, and a loop variable. A list or generator
comprehension is no literal collection, since it can be empty: `self.assertFalse([sql for sql in
statements])` can fail.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS049, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.

## Citations

NASA P10 Rule 5: "Any assertion for which a static checking tool can prove that it can
never fail or never hold violates this rule. (I.e., it is not possible to satisfy the rule
by adding unhelpful "assert(true)" statements.)"
