# TS022 assert-parameters

The severity is warning; the rule is opt-in by default and stable.

## Reports

A function asserts what it expects of its parameters, so a wrong argument fails at the call it
came from.

Reporting unit: Each function, where a function is a declaration, an anonymous function
expression, or a lambda bound to a name (`const read = (sector) => {}`, `f := func(n int)
{}`, `let f = |n: u32| n`). A single finding lists each parameter the entry window leaves
unasserted.

Anchor: The parameter list span, not the first offending parameter.

Carve-outs: Each parameter that can hold an invalid value is checked, in each language,
whatever its type; the standard says all arguments, and P10 says each function. The asserted
set is the entry window: the leading run of assert statements after an optional docstring,
where a Zig `std.testing.expect*` call is an assert statement whether it is spelled in full or
through a file alias such as `const expect = std.testing.expect;`.
A comment is not a statement and does not end the window, so `def f(v):  # note` followed by
`assert v > 0` passes. A declaration does not end the window either unless it reads the
parameter, so `const tokens = pairs.tokens;` ahead of `assert(open <= index);` leaves `open` and
`index` asserted at entry, while `const first = open + 1;` ahead of the same assertion leaves
`open` unasserted, because the function operated on it first. A Zig discard, `_ = name;`, does
not end the window and exempts the parameter it names: Zig rejects an unused parameter, so the
discard marks one the body never reads. A function whose body is not a block still has an empty
window, so
Python's one-line `def f(): ...` and an expression-bodied arrow `const f = (v) => v * 2`
report, while a signature closed by a semicolon carries no body at all and is silent, and so is an
Odin procedure whose body is `---`, the declaration a `foreign` block or a builtin package makes.

A parameter is exempt only where the language, not the author, proves it: a receiver, which is
Python `self` and `cls`, Rust `self`, and JavaScript and TypeScript `this`; a discard, which is Go,
Odin, and Zig `_` and Rust's `_`-prefixed names; a parameter whose type is `type`, which names a
compile-time type rather than a value; a Rust `&T` or `&mut T` reference, which the borrow checker
proves non-null, aligned, and initialized; and a Zig `*T` or `*const T` single-item pointer, which
the language proves non-null. A Zig `void` has one value, and a Zig allocator or `Io`, spelled
`std.mem.Allocator`, `mem.Allocator`, `Allocator`, `std.Io`, or `Io`, is a pair of pointers the
language proves non-null, so neither carries a value the callee can check; the TigerBeetle code
passes its allocators unasserted. There are three more shapes that carry no invalid value by type
and are exempt on the same ground: a boolean (`bool`, `boolean`), whose two values are both valid; a
function or closure type, read from the language's callback markers on the parameter's type or on
the bound of its generic (`F: FnOnce() -> R`, `impl Fn(u32)`, `func(int)`, `Callable`), since a
function value has no range; and a fieldless enum declared in the same file, `enum Kind { Bullet,
Ordered }`, whose every value is a variant. A method or a constant declared inside the enum is not a
payload. An enum declared in another file is beyond the file's horizon and reports, as does a
variant that carries a payload, which includes each Zig `union(enum)`, and a non-exhaustive Zig
enum, whose `_` member admits a value no variant names. A Zig `?*T`, `[*]T`, or `[]T`, a Go `*T`,
and an Odin `^T` can each be null or empty and are checked. A variadic `*args` or `**kwargs` holds
values and is checked.

A Python parameter annotated with names the file declares as aliases of a callable type,
`handler: SyncHandler | AsyncHandler` under `SyncHandler = typing.Callable[[Request], Response]`, is a
function value like one annotated `Callable` directly.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS022, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `macro-token-tree`, `bodiless-declaration`, `local-assert-binding`, `dot-directory-walked`, and `go-signature-continuation`.
