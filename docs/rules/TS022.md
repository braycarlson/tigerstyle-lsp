# TS022 assert-parameters

The severity is warning; the rule is opt-in by default and stable.

## Reports

A function asserts what it expects of its parameters, so a wrong argument fails at the call it
came from.

Reporting unit: Each function, where a function is a declaration, an anonymous function
expression, or a lambda bound to a name (`const read = (sector) => {}`, `f := func(n int)
{}`, `let f = |n: u32| n`). A single finding lists each parameter the entry window leaves
unasserted.

Anchor: The parameter list span, not the first offending parameter.

Carve-outs: Each parameter that can hold an invalid value is checked, in each language,
whatever its type; the standard says all arguments, and P10 says each function. The asserted
set is the entry window: the leading run of assert statements after an optional docstring,
where a Zig `std.testing.expect*` call is an assert statement whether it is spelled in full or
through a file alias such as `const expect = std.testing.expect;`.
A Zig guard is an assert statement too: an `if` whose branch only returns `error.Name`, `null`,
`false`, or `true`, reaches `unreachable`, returns `Set.Name` where `Set` is an error set the
function's return type names left of its `!` or the file declares as `error{...}`, or calls
`@compileError`, which fails the build on a `comptime` parameter. A guard asserts only the names
its condition mentions, so a parameter spelled in a `@compileError` message stays unasserted, and
a condition that adds or multiplies is not validation, because the arithmetic can overflow before
the check. A Python raise guard is an assert statement too: an `if` with no `elif` and no `else`
whose body is one `raise`, or one binding followed by the `raise` that consumes it, `message =
f'bad {value}'` then `raise ValueError(message)`. It asserts only the names its condition mentions,
so a parameter spelled only in the message stays unasserted, and a branch that also logs, returns,
or does any other work is a handled case rather than a check. A raise guard nests: an `if` whose
whole body is one raise guard is a raise guard too, `if value is not None:` holding `if value < 0:
raise ValueError('value')`, which is how TS023 has a compound check written, and it asserts the
names any of its conditions mention. No other language reads a branch
that raises as a guard, and a Python branch that returns early is not one, because it handles the
value instead of refusing it.
A comment is not a statement and does not end the window, so `def f(v):  # note` followed by
`assert v > 0` passes. A declaration does not end the window either unless it reads the
parameter, so `const tokens = pairs.tokens;` ahead of `assert(open <= index);` leaves `open` and
`index` asserted at entry, while `const first = open + 1;` ahead of the same assertion leaves
`open` unasserted, because the function operated on it first. A Zig or Python discard,
`_ = name`, does not end the window and exempts the parameter it names: Zig rejects an unused
parameter, so the discard marks one the body never reads, and Python code takes up the same
idiom. Only the discard exempts, as in Zig, where an unread parameter without one does not
compile: a Python parameter the body never mentions still reports, so the `*args` a Django
command's `handle` must accept takes its own `_ = args`. A discard after the parameter is read is outside the window and exempts nothing. Go
carries the same spelling without the idiom, since it accepts an unused parameter, so a Go
`_ = name` exempts nothing, and Rust marks an unused parameter with its `_` prefix instead. A
function whose body is not a block still has an empty
window, so
Python's one-line `def f(): ...` and an expression-bodied arrow `const f = (v) => v * 2`
report, while a signature closed by a semicolon carries no body at all and is silent, and so is an
Odin procedure whose body is `---`, the declaration a `foreign` block or a builtin package makes.

A parameter is exempt only where the language, not the author, proves it: a receiver, which is
Python `self` and `cls`, Rust `self`, and JavaScript and TypeScript `this`; a discard, which is Go,
Odin, and Zig `_` and Rust's `_`-prefixed names; a parameter whose type is `type`, which names a
compile-time type rather than a value; a Rust `&T` or `&mut T` reference, which the borrow checker
proves non-null, aligned, and initialized; and a Zig `*T` or `*const T` single-item pointer, which
the language proves non-null. A Zig `void` has one value, and a Zig allocator or `Io`, spelled
`std.mem.Allocator`, `mem.Allocator`, `Allocator`, `std.Io`, or `Io`, is a pair of pointers the
language proves non-null, so neither carries a value the callee can check; the TigerBeetle code
passes its allocators unasserted. There are three more shapes that carry no invalid value by type
and are exempt on the same ground: a boolean (`bool`, `boolean`), whose two values are both valid; a
function or closure type, read from the language's callback markers on the parameter's type or on
the bound of its generic (`F: FnOnce() -> R`, `impl Fn(u32)`, `func(int)`, `Callable`), since a
function value has no range; and a fieldless enum declared in the same file, `enum Kind { Bullet,
Ordered }`, whose every value is a variant. A method or a constant declared inside the enum is not a
payload. Outside Zig, an enum declared in another file is beyond the file's horizon and reports, as
does a variant that carries a payload. A non-exhaustive Zig enum reports too, because its `_` member
admits a value no variant names.

Zig reaches the same ground further, because its compiler proves each of these shapes closed: an
exhaustive enum; an error set, written `error{...}`, merged with `||`, or `anyerror`; a
`union(enum)` whose every payload is closed, a single-item pointer, or absent; a `struct`, packed or
not, whose every field is closed or a single-item pointer; an error union whose payload is closed,
`Failure!void`; and an optional of a closed type, `?Encoding`, when the body never forces its value
with `.?` or `orelse unreachable`, since a forced value is a precondition the entry window should
state. A union carrying a `u32` payload, an enum with a `_` member, and a `?*T` still report. The
type resolves through the declarations that name it, so an alias (`const Encoding =
Index.Encoding;`), a qualified path (`Index.Encoding`), and an import of a file beside the linted one
(`@import("line_index.zig").Encoding`, read from disk through the `@import` chain) all reach the
declaration. The declaration can be a call to a function that returns a type, `const Menu =
menu.MenuType(Platform);`, which reaches the container that function returns, so `Menu.Item.Toggle`
closes when `Toggle` does, as long as the function has one `return` of a container and every other
`return` lies inside it. An alias of a single-item pointer or a function type is exempt as the type
it names, so `listener: Listener` under `pub const Listener = *const fn (*anyopaque) void;` and
`hwnd: w32.HWND` under `pub const HWND = *opaque {};` are exempt, and an optional of one is exempt
only when it names a function, as `?*const fn` is. A declaration of `@This()` names the container
that holds it, so a `self: Self` inside an `enum` is that enum, and a file is the struct of its
top-level fields, so a file imported whole, `const Flags = @import("flags.zig");`, closes when each
of its fields does.
A file read this way makes the linted file's verdict depend on it, so a run never
records the linted file as clean in the cache. A package import (`@import("std")`,
`@import("json")`), a member of a `comptime` type parameter, and a field or payload whose type lives
in a third file stay beyond the horizon and report.

A Zig `?*T`, `[*]T`, or `[]T`, a Go `*T`,
and an Odin `^T` can each be null or empty and are checked. A variadic parameter, which is Python
`*args` and `**kwargs`, JavaScript and TypeScript `...rest`, Go `...T`, and Odin `..T`, holds values
and is checked, unless each reference to it spreads it whole into a call, as in
`super().get(request, *args, **kwargs)`: the function never reads what it gathered, and the callee
asserts its own parameters. A reference that indexes, rebinds, or passes the variadic unspread
still reads it. A Python `**kwargs` is exempt however the body uses it, because the interpreter
builds it as a fresh `dict` on each call, so the only check every function could carry,
`isinstance(kwargs, dict)`, can never fail. A guard on one of its keys, `'pk' not in kwargs`, can
fail and is still written where the function needs that key. A named parameter passed straight to a call is still checked, because TigerStyle
pairs an assertion at the caller with the one at the callee.

Zig reads further, into each use: a parameter whose every use accepts each value of its type carries
no precondition to assert, provided no assertion after those uses states a contract that belongs at
entry. Such a use compares it, switches on it, or passes it whole to a callee that accepts it the
same way. The callee resolves in the linted file, through an `@import` beside it, as a method on a
typed receiver, `writer.put_u32(value)`, and as a method reached through a chain of fields,
`linux.timers.stop(id)`, where each field's type comes from its declaration and a file that declares
`const Linux = @This();` is the struct whose fields it lists. The callee found is judged by its own
uses, so a `stop` that compares `id` accepts it, and a `recolor` that stores a `u32` `color` in a
field does not. A callee reached through a field typed by a `comptime` type parameter,
`app.platform.post(code)` under `platform: Platform`, stays beyond the horizon and reports.

An assertion after those uses belongs at entry unless it reads state the body changed: a path the
body assigns, `selection.count = count;` before `assert(selection.count == count);`, or the receiver
of a method that takes it as a mutable pointer, `linux.timers.stop(id);` before
`assert(!linux.timers.is_running(id));` under `pub fn stop(table: *TimerTable, id: u32) bool`. Such
an assertion is a postcondition, and moved to entry it would state something else. A method that
takes its receiver as `*const T` or by value changes nothing, so an assertion on that receiver after
the call is still a late contract. A binding counts as a copy of a parameter only when the
parameter's value can reach it, so a parameter named inside a `return` in the binding's value, the
`message` in `const context = create.lpCreateParams orelse return w32.DefWindowProcW(hwnd, message,
wparam, lparam);`, does not make `context` a copy of `message`, and a type declared in the body,
`pub const Builder = struct { ... }`, is not a copy of a parameter its methods mention. A name
after a member dot is a field rather than the parameter, so the `context` in
`callback(@ptrCast(done.context), done)` is not a use of a parameter named `context`, while the
one after a range, `buffer[0..count]`, is.

A Python parameter annotated with names the file declares as aliases of a callable type,
`handler: SyncHandler | AsyncHandler` under `SyncHandler = typing.Callable[[Request], Response]`, is a
function value like one annotated `Callable` directly.

A Python parameter typed as a request the framework builds, which is `HttpRequest`, `WSGIRequest`,
`ASGIRequest`, their `django` paths, and `rest_framework.request.Request`, carries no value the
function can check, because no call the author writes passes one. The same holds for a class the
file derives from one of those types, `class CompanyRequest(HttpRequest)`, and for each type the
`parameter_exempt_types` setting names, which is how a project exempts a subclass declared in
another file. The type must match exactly, so `HttpRequest | None` is still checked.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS022, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `macro-token-tree`, `bodiless-declaration`, `local-assert-binding`, `dot-directory-walked`, and `go-signature-continuation`.
