# TS030 if-braces

The severity is warning; the rule is on by default and stable.

## Reports

A branch whose body sits on another line carries braces, so a second statement cannot join it
silently.

Reporting unit: Each branch.

Anchor: The branch keyword.

Carve-outs: A single-line `if (a) assert(b)` is exempt, which is the shape TS047 asks for. An `else`
whose alternative is a block or another `if` is exempt; the inner `if` of an `else if` is measured
on its own, so `else if (b)` with its statement on the next line reports at that `if`. A Zig payload
capture is part of the header rather than the body, so `if (maybe) |value|` is measured against the
line the body opens on. An `if` or `else` is a branch arm only when the `if` that heads its chain
opens a statement, so each arm of a statement chain is measured, its last `else` included, and no
arm of a value chain such as `const v = if (a) x else if (b) y else z;` is, whatever closes the arm
before an `else`: a literal, a labeled block, or a `switch`. An `else` whose `if` cannot be found,
such as the `else` of a loop, is an arm when it opens a statement itself. The brace of a Zig
anonymous literal, `.{`, opens a value rather than a block, so an `if` that is an element of `.{ if
(a) x else y, z }` is a value expression and its `else` stays out of a statement too. An Odin `do`
body is measured from the `do`: `if a do work()` is exempt, and `if a do` with `work()` on the next
line reports.

## Does not report

The rule reaches JavaScript, Odin, TypeScript, and Zig. Go and Rust require braces on
each if, so an unbraced one does not parse. Python blocks are indentation, not braces.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS030, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shape that misfires here is `zig-else-clause`.

## Citations

consistency and defense in depth against \"goto fail;\" bugs."
