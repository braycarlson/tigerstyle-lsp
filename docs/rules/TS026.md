# TS026 assert-return-value

The severity is info; the rule is opt-in by default and stable.

## Reports

A function asserts the value it computes, so a wrong result fails where it was computed.

Reporting unit: Each return site, in a declaration, an anonymous function expression, or a
lambda bound to a name. Rust adds one synthesized site for a tail expression, and an
expression-bodied arrow function, `const double = (v) => v * 2`, is one site.

Anchor: The return site.

Carve-outs: The computed-value gate is the one gate: a site reports only when the returned value is
computed, which means it applies an arithmetic operator or a cast to a name, either in the return
expression itself or in the declaration that bound the returned name earlier in the body, so `let
doubled = value * 2; return doubled;` reports exactly as `return value * 2;` does. That leaves out a
forwarded parameter, a forwarded call, a composite literal, a returned function, a sentinel, a
constant, a bare field read, and an unwrap, none of which computes anything the function could
assert. A tuple, `(x as f32, y + 1)` at a Rust tail or `return (a + 1, b);`, is a composite literal
too, and so is a Python tuple written without parentheses, `return "%s__iexact" % name, None`, while
a call that wraps one, `Some((held, value + 1))`, still reports. A `*` or `**` that follows no value
is a dereference or an unpacking rather than a product, and an operator whose operands are literals
alone computes a constant, so `self.capacity.unwrap_or(2 * (1 << 20))` is an unwrap with a constant
default, while an operand reaches a name through a group, a call, an index, a receiver keyword, or a
postfix unwrap, as in `(a + 1) * 2`, `v.len() - 1`, `a[0] * 2`, `self.b + 1`, and Zig `blah.? + 1`.
That reading takes `(**self).size_hint()` and `*self.get(id).unwrap_or(&0)` as forwarded calls,
while `*a * b` still multiplies. A negated call whose every argument is a type or a literal,
`-std.math.inf(f64)`, is a sentinel too, since nothing it negates is a runtime value. A site passes
when each returned value is a literal or an identifier some assertion in the body mentions, or when
the statement immediately before it is an assertion, with any blank lines between the two ignored. A
return that carries an error, and a multi-value return from a fallible function, are exempt: the
other values are valid only on the success path, which no single assertion states. A multi-value
return whose last value is `ok`, the comma-ok flag of Go and Odin, `return transmute(f64)v + 1, ok`,
is such a return.

Where the function spells a return type, the type must be numeric after its wrappers are
peeled, because a bound is the postcondition the rule can state: Rust `Option<u32>` and
`Result<u32, E>`, Zig `?u32` and `!u32`, Odin `Maybe(int)`, Python `Optional[int]`,
TypeScript `number | null`, and a Go `(int, error)` pair each read as their inner number.
Where no return type is spelled, which is JavaScript and un-annotated Python and TypeScript,
the computed-value gate alone decides. A void function is exempt, and the void test knows
Rust `()` and `!` and Zig `void` and `!void`. Rust's tail site is the block's last statement
other than a comment, and is skipped when that statement is a declaration, an expression
statement, or a block-shaped construct such as a branch or a match. A tail that is itself a bare
block, such as the `#[cfg(not(debug_assertions))] { self as u32 }` that ends a function, is judged
and anchored by that block's own tail.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS026, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `tail-expression`, `closure-return`, `argument-closure-return`, `macro-tail-expression`, `node-shape-anchor`, `anonymous-container-scope`, `assert-then-return-gap`, and `chained-match-tail`.
