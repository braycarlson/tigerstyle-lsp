# TS003 too-many-parameters

The severity is warning; the rule is on by default and stable.

## Reports

A function takes at most `parameters_max` parameters; past that the arguments are easy to
mix up and belong in an options struct.

Reporting unit: Each function, where a function is a declaration, an anonymous function
expression, or a lambda bound to a name (`const wide = (a, b, c) => {}`, `var f = func(a, b
int) {}`, `let f = |a, b| a`, `f = lambda a, b: a`). A lambda passed straight to a call is
TS015's and is not counted here.

Anchor: The parameter list, from the opening parenthesis to the closing one.

Carve-outs: An implicit receiver does not count, and only a language that has one carves
anything out. Python drops `self` and `cls` when either opens the list, and Rust drops
`self`, whose `&self` spelling carries no name at all. Go, JavaScript, Odin, TypeScript,
and Zig carve out nothing, because none of them passes a receiver the signature does not
spell: a Zig `self` is an ordinary parameter under a conventional name, and a caller
supplies it like any other. A comma-separated segment counts only when it holds a name,
which drops a trailing comma, Python's positional-only `/`, and Python's keyword-only `*`.
A list holding nothing but comments counts as zero.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS003, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.
