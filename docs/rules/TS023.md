# TS023 no-compound-condition

The severity is warning; the rule is on by default and stable.

## Reports

A condition evaluates one boolean. A condition that joins two with `&&`, `||`, `and`, or
`or` is split into nested `if/else` branches, so the reader can see that each case is
handled.

Reporting unit: Each condition.

Anchor: The first token of the condition.

Carve-outs: An operator counts only at the condition's own depth. A parenthesised group is
not descended into, and an operator inside a call's argument list belongs to the call, so
`if any(a && b)` is quiet while `if (a && b) || c` reports for the `||` outside the group. A
condition that is one parenthesised group, negated or not, is read inside that group, so
`if not (a and b)`, `if !(a && b)`, and `if ((a or b))` report while
`if not (text or '').strip()` stays quiet. A guard written inside a macro's parentheses,
`matches!(kind, Pattern if a || b)`, ends at the parenthesis that closes the macro, whether
or not a comma precedes it.

The conditions read are the headers of `if`, `elif`, `else if`, `while`, `for`, and Odin's
compile-time `when`, the middle clause of a three-clause `for`, a `switch` `case` label in Go,
Odin, and JavaScript, and a `match` or `case` guard in Rust and Python. A `case` label ends at its
colon, so the `&&` of `return op.kind == .REGISTER && ok` on the line after `case .A, .B:`
belongs to that statement and not to the label. A `for` that walks a collection with `in`,
`of`, or `range` holds no condition and is not read, so `for x in a or b` is quiet and a
comprehension's filter reports once, at its own `if`. A Rust `for` that belongs to a type, in an
`impl Trait for &&&Type` header or a higher-ranked bound `for<'a>`, is no loop header, so the
`&&` of a reference type after it is not read. A JavaScript or Zig header is the
parenthesised group after the keyword, so a braceless `if (a && b) return 1;` and an
expression `if (a and b) 1 else 2` are read the same as a braced branch. A Python header
ends at its colon, so a single-line body after it is not part of the condition. A `return`,
an assignment, and a ternary without an `if` keyword are not conditions and are not read.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS023, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shape that misfires here is `node-shape-anchor`.

## Citations

TigerStyle: "Compound conditions that evaluate multiple booleans make it difficult for the
reader to verify that all cases are handled. Split compound conditions into simple
conditions using nested `if/else` branches. Split complex `else if` chains into `else { if
{ } }` trees."
