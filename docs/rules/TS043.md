# TS043 declaration-distance

The severity is info; the rule is opt-in by default and stable.

## Reports

A binding is declared where it is used and in the block that uses it, so a reader holds one
value at a time.

Reporting unit: Each declared name. A name reports once: for its scope where each use sits
inside one child block, otherwise for its distance where the first use is further away than
`declaration_distance_max` statements.

Anchor: The declared name.

Carve-outs: Each statement list is scanned, so a declaration at the top of a function is measured
against the function's statements, and a declaration inside a nested block is measured against that
block's own siblings, each once. A declaration between the binding and its use adds no distance,
because a table of bindings followed by a table of uses reads better than either interleaved, so
the message counts the statements in between that are not declarations and says so. An attribute or
a decorator adds no distance either: `#[cfg(feature = "x")]` above a statement belongs to that
statement rather than standing as one of its own. A declaration
whose value is a function or a closure is a definition rather than a variable and is exempt, the
value read through a JavaScript declarator too, `const getMarginX = el => ...` or `var swap =
function(elem) {...}`, as is
one whose name is screaming case, which is a constant, and one whose name is title case where the
language spells types that way, which is a type alias. A declaration the language marks constant
whose value is a literal is a constant too, whatever its case: Zig spells `const ratio: u32 =
86630;` and `const sources = [_][]const u8{ "a", "b" };` in snake case, and a value built only of
numbers, strings, enum literals, and type names holds nothing that could be computed later. A
template with a `${}` hole reads a name, so `` const text = `run ${code}`; `` is not a literal. A
declaration whose value reads a path that a statement before its first use assigns, as `const result
= prng.state[0];` ahead of `prng.state[0] ^= mixed;` does, is a snapshot: moving it would change
what it holds, so neither the distance nor the scope check reports it. The statement that assigns
may write through a dereference or with a compound operator: `let was_queued = *queued;` ahead of
`*queued = true;`, and `let held = atlas[*current].gles;` ahead of `*current += 1;`, are snapshots
too. A declaration whose value is
a call is measured like any other: the rule reports, it does not move code, and whether the call may
be delayed is the author's decision. The distance is measured to the nearest use of any name the
declaration binds, so a pair like Go's `value, ok :=` is quiet when either half is used at once. A
name that is never used again carries no distance and is quiet. A mention counts only on a word
boundary. The discard name a language spells, which is `_` wherever `discard_prefix` names one, is
not a binding and carries no distance: a later `_` is another discard rather than a use of this one.
A Go `var held int` with no initializer is a declaration measured to its first assignment or use,
and its type name is not one of its names, with an initializer or without: `var held int64 = -1`
binds `held` alone.

The scope check reports a declaration whose every later use sits inside one block of one
sibling `if`, `switch`, `match`, `try`, `with`, or bare block, in the block and not in the
header: `let held = value; if flag { work(held); }` asks for `held` inside the branch. A
use in the condition, uses split across two arms or two siblings, and a declaration binding
several names whose uses land in different blocks are not confined. A declaration is confined only
when each name it binds that is used again is used inside the same block, so `let (index, value)
= pairs[0]; if index > 0 { work(value); }` keeps `value` beside `index` and is measured for its
distance instead, while `let (index, value) = pairs[0]; if flag { work(index, value); }` reports
each name for its scope. A string that interpolates the name, `{held}` or `{held:?}` inside
`format!`, `write!`, `print!`, or a Python f-string, is a use like any other, so `print!("{held}")`
beside the block or in the other arm keeps `held` unconfined; an escaped `{{held}}` is text. A name
the lexer splits out of a Python f-string or a JavaScript template, `f"({cast}{obj})"` or
`` `${cast}` ``, counts the same way when it keeps a binding unconfined, while such pieces alone do
not confine a binding the scan otherwise sees no use of. A Python name that opens and closes with a
double underscore, a module's `__all__`, is read by the language itself, `import *` for one, so
its uses are not all in the file and it is exempt. A loop
body is not a
target, because a declaration moved into a loop is evaluated once per iteration, which is a
change of meaning rather than of scope.

A block that follows a statement is part of that statement rather than a statement of its own,
so it adds no distance while its text still counts as a mention. That is how tigerstyle-lsp's syntax
pass spells `let config = Config { … };`.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS043, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `nested-statement-count`, `comment-as-statement`, `multi-name-declaration`, `blank-identifier-binding`, `statement-list-shape`, `tuple-pattern-binding`, and `zig-comptime-var`.

## Citations

TigerStyle: "Calculate or check variables close to where/when they are used. **Don't
introduce variables before they are needed.** Don't leave them around where they are not.
This will reduce the probability of a POCPOU (place-of-check to place-of-use), a distant
cousin to the infamous TOCTOU. Most bugs come down to a semantic gap, caused by a gap in
time or space, because it's harder to check code that's not contained along those
dimensions."

TigerStyle: "Declare variables at the **smallest possible scope**, and **minimize the
number of variables in scope**, to reduce the probability that variables are misused."

NASA P10 Rule 6: "Data objects must be declared at the smallest possible level of scope."
