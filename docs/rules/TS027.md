# TS027 explicit-sized-types

The severity is warning; the rule is opt-in by default and stable.

## Reports

A type spells its width, so the same program runs the same way on a smaller target.

Reporting unit: Each type occurrence.

Anchor: The type node.

Carve-outs: The architecture-dependent names are Rust and Zig `usize` and `isize`, and Go and
Odin `int`, `uint`, and `uintptr`. An occurrence that follows a cast operator is exempt, as is a
conversion spelled with the type itself, Go and Odin `int(x)` and `uint(x)`, which chooses a
width for one expression rather than storing one. A `uintptr` conversion is exempt only when
applied to a pointer expression, since a pointer's integer view has no width to choose.

A name never justifies a width on its own. A local or a parameter is exempt when the function uses
it as an index: it appears directly inside `[` `]`, at either end of a range or a slice written
inside them, or beside a comparison on a line that names `len` or `cap`. Rust and Zig index with
`usize` and compare against a `usize` length, and Zig's slice boundaries are `usize` by language, so
the width there is the language's, not the author's; Go and Odin index with any integer, and the
same exemption applies for parity. A name typed through a pointer is read the same way, so a Zig
`cursor: *usize` that the function writes as `text[cursor.*]` is exempt. A struct field, a constant,
and a static take the same test read over the whole file rather than one function: `position: usize`
in a cursor that the file writes `source[self.position]` is exempt, since a stored index still
indexes, while `count: usize` in a struct reports, since a stored count is exactly where the
standard wants `u32`. An element width, `Vec<usize>`, `Option<usize>`, or `[]usize`, is exempt
anywhere but in a field, so the type of a local, a parameter, or a return value may carry it; a
later type argument is an element as the first is, `HashMap<String, usize>` or
`std.AutoHashMap(u32, usize)`, while a tuple's element, `(u32, usize)`, is no type argument. The
same element width inside a struct field, `offsets: Vec<usize>` or `lines: [usize; 4]`, reports,
because the field stores it, and so does a field of a tuple struct, `struct Offsets(Vec<usize>);`,
and a Zig file's own top-level field such as `limbs: std.ArrayList(usize),`. A field of a struct
declared inside a function, such as an anonymous `options: struct { count: ?usize = null }`, reads
as a local. The Zig element widths are `?usize`,
`[]const usize`, a type constructor's argument such as `std.ArrayList(usize)`, and the type argument
of an allocating call such as `arena.alloc(usize, count)`; a value's width handed to a generic
function, such as `prng.int(usize)`, is no element and reports. A `Range<usize>`, and the rest of
the `Range` family, is exempt anywhere: the type is the slice index the language defines.

A return type is exempt when each `return` and the tail expression hand back the language's width:
a name the function indexes with, read through a `self.` or other receiver, or bound by a `let`
whose value ends in `.len()`, `.count()`, `.position(..)`, or `.cap()`, optionally stepped by a
literal (`position + 1`) and optionally wrapped in `Ok(..)`, `Some(..)`, or `Err(..)`; or an
expression that itself ends in one of those calls. A returned tuple or computation reports.

A signature is exempt only where the other side dictates it: a function inside a Rust `impl ... for
...` block, whose signature the trait fixes, read through a header that wraps its `for` onto a later
line before the block opens, and a function on a foreign boundary, a line or an
enclosing block carrying Rust `extern`, Zig `callconv`, `export`, or `extern`, Odin `foreign`, or Go
`Call` or `Syscall`. The line alone decides it, whether or not the parser reads a function there, so
a bodiless `extern "c" fn memcpy(*anyopaque, *const anyopaque, usize) *anyopaque;` and a field
typed `*const fn (*anyopaque, len: usize) callconv(.c) ?[*]u8` are dictated. An Odin procedure
whose body is `---` is dictated too, since it declares a signature that a foreign library or the
compiler defines, as the `uintptr` of a builtin's declaration does. A function the file hands over
as a value is dictated the same way, by the
function type it fills: the file names it without calling it, as a `std.mem.Allocator` vtable does
with `.alloc = alloc`, a `std.Io.Reader` with `.stream = stream`, and
`std.debug.FullPanic(panic_handler)` with a panic handler. A function written in place as a call
argument, a field value, or the value of a member assignment is handed over the same way, as Go's
`sort.Slice(items, func(i, j int) bool { ... })` is, and so is a function an anonymous container
declares when the file names it through that container, `struct { fn write(...) usize {} }.write`,
with or without parentheses that wrap exactly the container, `(struct { ... }).write`. The position
is read where the container expression starts, so `const write = struct { ... }.write;` is an
untyped alias. An untyped alias such as `pub const build = run;`, a comparison, an export, and an
Odin procedure group `proc{first, second}` hand nothing over, since none of them fixes a signature,
and neither does a procedure type named as a field's type. A switch prong hands a function over
exactly when the switch itself would: a prong of a switch that is a field value, an argument, or a
return value fills the function type the switch fills, while a prong of a switch bound to an untyped
alias does not. Any other parameter or return type reports, including the parameters of a closure
bound to a name, since a closure is a function; `let f = |x: usize| x;` reports. A Zig completion
parameter, `result: RecvError!usize`, is exempt, since the completion's type is the callee's.

An occurrence that qualifies a name, as `usize::MAX` does, is not a type and is silent. A fixture
file is exempt: one under a snapshot or `testdata` directory, or one under a `test`, `tests`,
`__tests__`, or `spec` directory that holds no test of its own, which is a formatter or
highlighter input rather than a test. A file holds a test when it carries `#[test]`, `cfg(test)`,
or `@(test)`, a `test` block, a function whose name opens with `test`, `Test`, `bench`, or
`Benchmark`, or a callback handed to `test`, `it`, `describe`, or `bench`. A type inside a `.{
... }` tuple literal is exempt, as a list of widths under comptime iteration. A line inside a
`macro_rules!` body is exempt, because no signature is parsed there.

## Does not report

The rule reaches Go, Odin, Rust, and Zig. JavaScript and TypeScript numbers are IEEE doubles
and bigint is arbitrary precision, so there is no sized type to require. Python integers
are arbitrary precision, so there is no sized type to require.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS027, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `go-architecture-type`, `memory-sized-measure`, `completion-parameter-width`, `macro-qualified-type`, `turbofish-argument`, `builtin-type-argument`, `architecture-type-anywhere`, `macro-token-tree`, and `multi-name-destructure-type`.
