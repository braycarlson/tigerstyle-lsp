# TS055 trailing-comma

The severity is info; the rule is opt-in by default and stable.

## Reports

A wrapped list ends with a trailing comma, so the formatter keeps one element per line and the
next element is a one-line change.

Reporting unit: Each wrapped list.

Anchor: The last token of the last element, where the comma goes.

Carve-outs: A list is a bracket pair whose opener and closer sit on different lines and whose
contents hold a comma at the top level. Each parenthesis and square bracket qualifies: a parameter
list, a call, a tuple, an array, and an attribute. A brace qualifies only where it opens a data
structure rather than a body: after `=`, `:=`, `(`, `[`, `,`, `:`, `.`, `return`, `import`,
`export`, `struct`, `enum`, or `union`, or after a name that follows one of those, `let`, `const`,
`var`, or `]`. A Rust `struct S {`, `enum E {`, `use x::{`, `Config {` in a `let`, and a match arm's
`{` are therefore lists, and a function body, an `if` body, a `match` body, and a `switch` body are
not. A brace that closes the header of a branch, a loop, or a switch is that construct's body, so
Odin's `switch m.mode {` and `if x != .None {` hold statements rather than elements. A brace that
opens a line after a name is a block in a language whose statements end at a newline, which is Odin
and Go, as under `total: int`. A body that holds a top-level `;` is never a list.

The last element is exempt when it ends in a block, since `rustfmt` and `zig fmt` write no comma
after a block arm or a nested declaration, and when it is a spread or a struct update, since a comma
after `...rest` in a parameter list and after `..base` in a struct literal is a syntax error. A
comment between the last comma and the spread does not hide it: the element is read from its first
token past the comments. A matcher in a Rust `macro_rules!` definition, the group before `=>` and
each group inside it, is a pattern rather than a list, since a comma there changes which invocations
match, and a last element that is a repetition, `$(...),+` or `$(...)*`, supplies its own
separators. A list that a transcriber writes is code and still reports.

The fix inserts the comma after the last element, and only where the list already holds one
element per line with the closer on a line of its own, which is the layout the formatter keeps
once the comma is there. A hugged list such as `}, 0);`, or a packed one with two elements on a
line, still reports but carries no fix, since the comma alone would leave `}, 0,);` for the
formatter to lay out again.

A bracket that holds a comprehension or a generator, `for` then `in` at its own depth as in `[item
for _, key, item in pairs if key == wanted]`, is no list: a trailing comma there is a syntax error.

## Does not report

The rule reaches JavaScript, Odin, Python, Rust, TypeScript, and Zig. The Go grammar requires the
trailing comma when the closing delimiter starts a new line, so a wrapped list without one does
not compile.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS055, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.
