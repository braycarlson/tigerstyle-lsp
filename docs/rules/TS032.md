# TS032 snake-case-names

The severity is warning; the rule is opt-in by default and stable.

## Reports

A function, variable, or file name is snake_case, so casing carries no meaning of its own.

Reporting unit: Each name, and once per file for the file name.

Anchor: The name token; the file-name finding sits at the first byte of the file.

Carve-outs: The leading and trailing underscores are trimmed before the tests, and a screaming name
or a language-constant name is exempt. A bare identifier pattern is the one pattern that declares a
name, so an identifier followed by `{`, `(`, or `,` in pattern position yields nothing and `let
Input { input } = load()` does not report the type. The same test holds inside a declaration group,
so the `Some` of `let (Some(a), Some(b)) = ...` is a constructor rather than a name while Go's `var
( ... )` block still declares each name it opens a line with. Go peels the first character rather
than skipping an exported name outright, so `ReadSector` reports with the suggestion `Read_sector`
while `Read_sector` passes. An exported name that opens with an acronym from the TS042 table writes
the whole acronym in capitals, so `TLSUnique` suggests `TLS_unique`, `HttpServer` suggests
`HTTP_server`, and `IPv4Address` suggests `IPv4_address`, while each renamed form passes. The fix
renames the declaration and each use the file's binding table resolves to it, and only where those
are all the uses there are: a binding inside a function, or in Zig and Rust a declaration without
`pub` or `export`. A public declaration, a field, a method, and a top-level name in a language whose
other files share the namespace keep uses beyond this file or behind member access, so they report
without a fix, and so does a rename whose new spelling another binding in the file already holds.
The edits run in source order, so a use above the declaration is renamed as surely as one below it.
A Zig test that names the declaration, `test readSector {`, is a use the binding table does not
hold, and the fix renames it with the rest; when two declarations in the file share the name, the
test's target is ambiguous and the finding reports without a fix. A declaration whose value's
trailing dotted segment equals the declared name is a foreign alias and is exempt, which is the
carve-out TS037 and TS045 share; against a dotted segment the name may also match with its
surrounding underscores trimmed, so `const _installLazyMethods = util.installLazyMethods;` keeps the
foreign spelling. A declaring keyword that follows a star and completes one of the language's raw
pointer prefixes, as `const` does in Rust's `*const T`, spells a type rather than opening a
declaration and names nothing.

A field is a variable name and reports in each language, so Go's `MaxSize int`, a Rust or Zig
struct field, a Python class attribute, and a Python `self.` or `cls.` attribute at its first
assignment in the file all report. JavaScript and TypeScript class methods, getters, setters,
static members, fields, object-literal keys, and method shorthand report through the same
path; a destructuring pattern's keys and a type literal's members are uses of another
declaration's names and do not. A TitleCase name is exempt where the language spells types that
way, which is JavaScript, Odin, Python, TypeScript, and Zig, so a title-case binding is left to
TS042. Go's `Benchmark`, `Example`, `Fuzz`, and `Test` prefixes are exempt, since the
toolchain dictates them. A hook a test framework calls by its spelling is dictated the same way:
Python's `unittest` hooks, `setUp`, `tearDown`, `setUpClass`, `tearDownClass`, `setUpModule`,
`tearDownModule`, `asyncSetUp`, `asyncTearDown`, `runTest`, `maxDiff`, and `longMessage`, the
`TestResult` methods a runner overrides, `addError`, `addFailure`, `addSkip`, `addSubTest`,
`addSuccess`, `addExpectedFailure`, `addUnexpectedSuccess`, `startTest`, `stopTest`,
`startTestRun`, and `stopTestRun`, Django's `setUpTestData`, an `ast.NodeVisitor` method named
`visit_` and a node class, `visit_ImportFrom`, and a JavaScript `beforeEach` or `afterEach` hook.
A camel-case helper of the author's own, `assertChildNodes`, still reports.

The file name is checked once: the stem before the first dot must carry no uppercase letter
and no hyphen, so `VsrState.zig`, `MyModule.rs`, `camelCase.py`, `CamelFile.go`, and
`my-module.js` each report. A screaming stem such as `README` or a fixture's `TS032` is
exempt, as a screaming identifier is, and `__init__.py` passes on its own.

A Python stub, a `.pyi` file, restates a module the runtime defines, so a name it declares is the
runtime's spelling, fixed by that module as an `extern fn` name is by the linker, and is exempt:
`def getLevelName(level)` in `logging/__init__.pyi` and the keyword parameter `opt_str` of
`optparse.pyi` name what CPython names. A parameter before the `/` is positional only, a name no
caller spells, so it stays the stub's own and reports, and so does a declaration the stub marks
`@type_check_only`, which exists for the type checker alone.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS032, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `re-export-alias`, `composite-literal-key`, `type-switch-binding`, `type-argument-name`, `anonymous-container-member`, `composite-literal-element-name`, `composite-literal-method-name`, `container-value-name`, `dot-directory-walked`, `empty-container-in-a-field-type`, and `go-signature-continuation`.

## Citations

TigerStyle: "Use `snake_case` for function, variable, and file names. The underscore is
the closest thing we have as programmers to a space, and helps to separate words and
encourage descriptive names. We don't use Zig's `CamelCase.zig` style for "struct" files
to keep the convention simple and consistent."
