# TS035 conditional-compilation

The severity is warning; the rule is opt-in by default and stable.

## Reports

A single program is built for each target, because a branch taken at build time is a branch no
test covers.

Reporting unit: Each line, plus one report at line one for a file whose name selects a target; a
line reports only the first marker it carries.

Anchor: The marker's span; the first line for a file-name constraint.

Carve-outs: The markers are Rust `#![cfg(`, `#![cfg_attr(`, `#[cfg(`, `#[cfg_attr(`, and
`cfg!(`; Go `//go:build` and `// +build`, plus a file whose stem ends in a `GOOS` or `GOARCH`
suffix such as `_windows`, `_linux`, or `_amd64`, which the toolchain constrains without any
in-file marker; Odin `#+build`, `//+build`, `#config(`, `ODIN_ARCH`, `ODIN_BUILD_MODE`,
`ODIN_DEBUG`, `ODIN_DISABLE_ASSERT`, `ODIN_NO_BOUNDS_CHECK`, `ODIN_OPTIMIZATION_MODE`, and
`ODIN_OS`; Zig `@import("build_options")`, `build_options.`, `builtin.abi`, `builtin.cpu`,
`builtin.link_libc`, `builtin.mode`, `builtin.os`, `builtin.single_threaded`, and
`builtin.target`.

A Rust marker is skipped only when its predicate names `test` as an atom: `#[cfg(test)]`,
`#[cfg(any(test, feature = "x"))]`, `#[cfg(not(test))]`, `cfg!(test)`, and
`#[cfg_attr(test, ...)]` are the test harness rather than a second program. The predicate is
parsed from the marker's own parentheses, so `feature = "latest"`, a trailing comment that
says `fastest`, and a `fn contest` on a nearby line skip nothing. `#[cfg(debug_assertions)]`
reports, because it builds two programs and the standard flags each use.

A language whose markers are ordinary expressions rather than attributes or build comments,
which `conditional_markers_need_a_branch` names and which is Odin and Zig, reports an
expression marker where the line opens a branch before it (`when ODIN_OS == .Windows`,
`if (builtin.os.tag == .linux)`) or binds it to a constant (`is_windows :: ODIN_OS ==
.Windows`, `const native_os = builtin.os.tag;`, `const build_options =
@import("build_options");`), since the branch on the alias is the conditional. A directive
marker, one opening with `#` or `//`, needs no branch. A marker that falls inside a comment or
a string is quiet, because a doc example and a printed platform name build nothing; a marker
that is itself a comment or a directive line, which is what Go's `//go:build`, `// +build`,
and Odin's `#+build` are, is exempt from that test. A `// +build` line directly under a
`//go:build` line is the same constraint spelled twice and reports once.

## Does not report

The rule reaches Go, Odin, Rust, and Zig. JavaScript, Python, and TypeScript have no build
step; a check of the platform, the environment, or the interpreter version is a runtime
branch, and the program shipped is one program, so those languages carry no markers.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS035, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `marker-inside-a-comment` and `node-shape-anchor`.

## Citations

NASA P10 Rule 8: "The use of conditional compilation directives is often also dubious, but
cannot always be avoided. This means that there should rarely be justification for more
than one or two conditional compilation directives even in large software development
efforts, beyond the standard boilerplate that avoids multiple inclusion of the same header
file. Each such use should be flagged by a tool-based checker and justified in the code."
