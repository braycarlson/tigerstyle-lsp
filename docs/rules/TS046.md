# TS046 allocation-grouping

The severity is info; the rule is opt-in by default and stable.

## Reports

An allocation and the defer that releases it sit together, set off by blank lines, so a missing
defer is visible.

Reporting unit: Each defer statement.

Anchor: The defer statement.

Carve-outs: Each `defer` is the release half of a pair, and Zig's `errdefer` is a defer. The
standard speaks of "the corresponding `defer` statement", so no word in the deferred text is
required: `defer cancel()`, `defer wg.Done()`, `defer mu.Unlock()`, and Odin's `defer
delete(values)` all pair with the statement before them. A defer that opens a block, `defer func()
{ ... }()` and Zig's `defer { ... }`, is read to the block's own end. A defer that is the first
statement of its block has nothing to pair with and is not reported.

The allocation is the statement immediately before the defer, not the line before it, so a
multi-line allocation still pairs whole. The line below counts as blank when it is empty or when
it opens with a closing `}`, alone or as `} else when B {`, since a defer at the end of a block
needs no separator. An error check between
the acquisition and its defer, `if err != nil { ... }`, and an earlier defer in a chain of them
are part of the pair rather than a gap.

The allocation also takes in the statements directly above it that build the same thing. A Zig
declaration whose value is `undefined` and whose name the pair names is the storage an in-place
acquisition fills, so `var built: Built = undefined;` above `try built.init(gpa);` and its defer is
one group, and so is the `var buffer` that `lockStderr(&buffer)` borrows. A statement that writes
the path the defer releases belongs to the acquisition too, so a run of `formatters.css = null;`
lines before `errdefer formatters.deinit(gpa);` is one group, while `built.tokens = ...` above an
acquisition of `built.pairs` is not. A declaration directly above that the defer names belongs to
the group when the acquisition assigns it, `var texture = try gpa.create(Texture);` above `texture.*
= .{ ... };` and `errdefer gpa.destroy(texture);`, or when the acquisition never names it, which is
a second resource the same defer releases, `var section` above `var params` and `defer {
section.deinit(); params.deinit(); }`, or a value saved for the defer to restore, `const level =
std.testing.log_level;` above the line that changes it. A declaration the defer does not name stays
outside, so `var iter = Iterator{ ... };` above `var res = try parse(gpa, &iter);` and `defer
res.deinit();` still reports.

A defer set off from the statement above it by a blank line pairs with that statement only when the
defer names something the statement declares, writes, calls a method on, or passes by address. A
defer that names none of those stands alone, such as `errdefer shadow.failed = true;` after a guard
or `errdefer std.debug.print(...)` after a call, and a lone defer set off by blank lines is quiet.

## Does not report

The rule reaches Go, Odin, and Zig. JavaScript and TypeScript free by garbage collection
rather than at a defer, so the paired-allocation shape has no syntax to anchor on. Python
frees by refcount rather than at a defer, so the paired-allocation shape has no syntax to
anchor on. Rust frees on drop rather than at a defer, so the paired-allocation shape this
rule looks for has no syntax to anchor on.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS046, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `defer-opening-a-block`, `anonymous-container-scope`, and `comment-before-defer`.

## Citations
