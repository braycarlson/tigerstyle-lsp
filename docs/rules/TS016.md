# TS016 no-dynamic-alloc

The severity is warning; the rule is opt-in by default and stable.

## Reports

All memory is reserved during initialization, so no later call can fail for want of it.

Reporting unit: Each allocating site: one finding per call, per allocating macro invocation, per
heap-backed collection literal, per built string, and, in Python, per slice copy.

Anchor: The whole call, rather than the callee name alone; the opening bracket of a literal; the
string token of a built string; the `+` of a string concatenation.

Carve-outs: The rule reads the program in two phases and reports only the second. A function is
initialization when its name is exactly `__init__`, `init`, `main`, `new`, `reserve`, `setUp`,
or `setup`, or when each call to it in the file comes from an initialization function, read from
the file's call table, so a helper that only `main` and `init` call is initialization and a
helper that `work` also calls is not. A function nobody in the file calls runs after
initialization, and so does a closure or a lambda, whose call time the text does not show. An Odin
procedure literal bound by `::` is the function its declaration names, so `main :: proc() { ... }`
is `main` and the helpers only it calls are initialization. Any code outside a function is
initialization. A prefix is not a name: `init_pool`, `build_response`,
`from_request`, and `make_key` are watched, and so are `close`, `shutdown`, `deinit`, `destroy`,
`teardown`, and `default`, which allocate after initialization when they allocate at all. The
file's path exempts nothing, and an allocation inside `Err(` reports like any other.

The test scope is exempt, a choice rather than a language fact: a test allocates its fixtures and
the allocation is the test's own, not the program's. The test scope is a test file by path, a test
function or a test callback, a `#[test]` or `cfg(test)` attribute above the enclosing frame, or a
file under a `testing` directory. A top-level declaration without `pub` or `export` that only test
code reaches is test scope too in Zig and Rust, where a declaration spells its visibility: a helper
function or a fixture type whose every reference in the file sits in a test or in another such
declaration, read to a fixed point, so a `Recorder` type that only a test helper and a test name is
test code, and so are its methods. A local block is exempt, which in Zig is a `comptime`
declaration, a `test` declaration, or a labeled type expression. Zig exempts any call whose callee
text names `testing.allocator`.

A Zig growth method allocates only when its failure can be `error.OutOfMemory`, since each Zig
allocation fails with that error. A call that stands alone as a statement cannot fail at all,
because Zig rejects a discarded error union, so `set.insert(rule)` on a bounded set is quiet, with
or without a comment on the line above it. A call whose `catch |err| switch (err)` names each error
it returns without `OutOfMemory` is quiet too, and so is a call under `try` in a function whose
declared error set, `error{Overflow}!void`, leaves `OutOfMemory` out. A bounded container that fails
with its own `error.Full` is the common case.

A call allocates when its callee names an allocating function whole, when the last two path segments
of the callee, read with any `::<...>` turbofish skipped, name one, or when it is a method call
whose leaf is an allocating method. Rust: `Vec::with_capacity`, `Vec::from`,
`String::with_capacity`, `String::from`, `Box::new`, `Rc::new`, `Arc::new`,
`HashMap::with_capacity`, and the other constructors that reserve memory, through any qualifying
path or turbofish, so `std::rc::Rc::new` and `Vec::<u8>::with_capacity` report; the methods `clone`,
`collect`, `concat`, `extend`, `insert`, `into`, `into_boxed_slice`, `into_boxed_str`, `join`,
`or_default`, `or_insert`, `or_insert_with`, `or_insert_with_key`, `push`, `push_str`, `read_line`,
`read_to_end`, `read_to_string`, `read_until`, `repeat`, `reserve`, `resize`, `to_owned`,
`to_string`, and `to_vec`, so `.collect::<Vec<_>>()` reports, and so do a read that grows the buffer
it is handed and an entry insertion that grows a map; the macros `vec!` and `format!`; and `+` or
`+=` with a string literal on its right, which only `String` accepts. Zig: `alloc`, `create`,
`dupe`, `realloc`, `allocPrint`, `initCapacity`, `ensureTotalCapacity`, `toOwnedSlice`, and the
growth methods `addOne`, `append`, `appendNTimes`, `appendSlice`, `insert`, `put`, and
`putNoClobber`, on a managed or an unmanaged container alike; `std.fmt.allocPrint`,
`std.mem.concat`, and `std.mem.join`. Go: `make`, `new`, `append`, `string`, `fmt.Sprint`,
`fmt.Sprintf`, `fmt.Sprintln`, `strings.Join`, `strings.Repeat`, `strings.Split`, a `+` with a
string literal, and the composite literals that live on the heap: `[]T{...}`, `map[K]V{...}`, and
`&T{...}`. Odin: `make`, `new`, `append`, `reserve`, `resize`, `mem.alloc`, `strings.clone`,
`strings.builder_make`, `strings.concatenate`, `fmt.aprintf`, `fmt.tprintf`, and the literals
`[dynamic]T{...}` and `map[K]V{...}`. JavaScript and TypeScript: `new Array`, `new Map`, `new Set`,
`new Object`, `new ArrayBuffer`, each typed array constructor, `JSON.parse`, `Object.assign`,
`Object.create`, the methods `concat`, `filter`, `map`, `push`, and `slice`, an array literal, an
object literal including `{ ...x }`, a template literal, and `+` with a string literal. Python:
`list`, `dict`, `set`, `tuple`, `str`, `sorted`, `bytearray`, `deque`, the methods `append`, `copy`,
and `join`, a list, dict, or set literal or comprehension, a slice `x[a:b]`, an f-string, and `+`
with a string literal. A slice an assignment writes into, `results[n:] = values`, copies nothing and
is quiet. A bracket that opens where a literal would and that a `=` or a JavaScript `of` follows is
a destructuring pattern, `const [key, value] = entry`, `for (const [key, value] of entries)`, or
Python's `[c] = as_series([c])`, and binds names rather than building a collection; a bracket that
`in` follows is still read, since `[value] in values` builds a list.

A Rust constructor that reserves no memory is not an allocating site, because the allocation
happens at the call that grows the value, which reports on its own. `Vec::new`, `String::new`,
`HashMap::new`, `BTreeMap::new` and the other empty collection constructors, `Vec::default`,
`String::default`, and a `vec![]` with nothing between its brackets are quiet, so
`let mut cases = String::new();` is silent and the `cases.push_str(...)` that fills it reports.

A composite literal is read from its opening brace: the brace is a literal when the token before
the type name, or before the `&` or `*` that precedes it, opens an expression, which is `=`, `:=`,
`,`, `(`, `[`, `return`, the language's iteration word, or a `:` that does not follow a `case` or
`default` label or a declared name's annotation. A brace after `}` is not read as a literal,
because a `for` header may end with one. Go's `T{...}` and `[N]T{...}` and Odin's `T{...}`,
`&T{...}`, `[]T{...}`, and `[N]T{...}` are values, which the language places on the stack, and are
not reported; `strings.Builder{}` is a value too and its growth happens inside its methods.

Python is a heuristic. There is an allocation in nearly every Python expression, so the rule names
the shapes whose allocation is the point of the expression and stays silent on the rest: an integer
addition, an attribute read, and a function call all allocate too, and none reports. A Zig
`writer().print` allocates only when the writer belongs to an ArrayList, which the text does not
show, so it is not reported. A Rust `write!` or `writeln!` grows its destination only when that is a
`String` or a `Vec`, which the text does not show either, so it is not reported. A Rust `.clone()`
is quiet where the text shows the receiver owns no heap: the call is the whole of an index,
`source[range.clone()]`, which only a range or an integer can be; or the receiver is one name whose
declaration in the file, found through the binding table, carries a primitive or a `Range` family
type annotation, through any `&`, `&mut`, or lifetime, or is a `let` whose value is a range
expression. Any other `.clone()` reports, as does each `.into()`, since the text does not show the
type. A `+` whose right operand is a byte string, `b"..."`, is arithmetic on a length or a slice and
never a `String` concatenation, so it does not report.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS016, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `macro-token-tree`, `chain-anchor-into-macro`, `labelled-block`,
`go-test-allocation`, `destructure-target-literal`, and `test-block-allocation`. A `.clone()` on a
`Copy` value whose declaration the file does not show, or an `.into()` on one, reports though it
allocates nothing, and a TypeScript object type written on a local's annotation reads as an
object literal.
