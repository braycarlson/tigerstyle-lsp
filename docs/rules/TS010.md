# TS010 no-pass-in-except

The severity is error; the rule is on by default and stable.

## Reports

A handler that does nothing hides the failure it caught.

Reporting unit: Each handler, and each `with` statement that suppresses.

Anchor: The `except` keyword, or the `with` keyword of a suppressing context manager.

Carve-outs: A handler reports when it catches broadly and its body, ignoring comments and blank
lines, is exactly one of `pass`, `...`, `continue`, `return`, or `return None`, since each
drops the error and carries nothing to the caller. The body reads the same whether it sits on
the `except` line, `except Exception: pass`, or on the lines below it. A body that logs,
re-raises, or returns a value passes.

A handler catches broadly when it is bare, `except:`, or when it names `Exception` or
`BaseException`, whether alone, qualified as `builtins.Exception`, bound by `as`, or as any
member of a tuple, so `except Exception as error: pass` and `except (ValueError, Exception):
pass` report. A handler that names only specific exception classes is quiet whatever its body:
`except ImportError: pass` around an optional import, `except ValueError: pass` around a
lookup that may miss, and `except TemplateNotFound: continue` in a loop that tries the next
loader each name the one failure the code expects and decide that doing nothing is the right
response to it. That is the error handled by name, as TS028 words the standard, while a broad
handler drops each failure the block can raise, the unexpected ones with the expected one.

A handler that carries a comment inside it is exempt, since the comment is the "why" the
standard asks for and the reader can weigh it. A comment is inside when it sits on the `except`
line, which takes in the trailing comment of a handler written on one line, or on a line
indented deeper than the `except` keyword. A comment below the handler at the keyword's own
margin or shallower opens the code that follows and exempts nothing.

A `with contextlib.suppress(...)` or `with suppress(...)` statement reports at the `with`
keyword when its arguments name `Exception` or `BaseException`, since the context manager is a
handler whose body is `pass`. A `with suppress(KeyError):` names the failure it expects and is
quiet, like the `except KeyError: pass` it stands for.

## Does not report

The rule reaches Python. Go, Odin, Rust, and Zig have no exception handler, so there is no
empty one to catch; Rust's empty error arm, `Err(_) => {}` in a `match` or an empty `if let
Err(_)` body, is the same shape and is reported by TS028 no-silent-error-swallow. JavaScript
and TypeScript have no pass statement; an empty catch is reported by TS028.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS010, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.
