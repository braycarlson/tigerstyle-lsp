# TS052 no-panic-recovery

The severity is error; the rule is on by default and stable.

## Reports

A crash stays a crash, because a recovered panic runs on from state the program has already
proven wrong.

Reporting unit: Each recovery site.

Anchor: The recovering call, the exception name in the handler, or the event name in the registration.

Carve-outs: Go reports a call to `recover` that is not a method call and not the declaration of a function by
that name. Rust reports a call to `catch_unwind`, however the path is spelled. Python reports an
`except` clause that names `AssertionError`, alone or in a tuple; `except BaseException:` is TS009's.
JavaScript and TypeScript report a listener for `uncaughtException` or `unhandledRejection`
registered on `process` through `on`, `once`, `addListener`, `prependListener`, or
`prependOnceListener`, and an assignment to `onerror` on `window`, `self`, or `globalThis`.

Nothing is exempt. A recovery in a test is a recovery.

## Does not report

The rule reaches Go, JavaScript, Python, Rust, and TypeScript. Odin and Zig have no way to
recover from a panic; an assertion failure ends the process.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS052, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.

## Citations

TigerStyle: "Assertions detect programmer errors. Unlike operating errors, which are expected
and which must be handled, assertion failures are unexpected. The only correct way to handle
corrupt code is to crash."

NASA P10 Rule 1: "Restrict all code to very simple control flow constructs; do not use goto
statements, setjmp or longjmp constructs, and direct or indirect recursion."
