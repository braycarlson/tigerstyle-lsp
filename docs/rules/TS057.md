# TS057 callback-name-prefix

The severity is info; the rule is opt-in by default and stable.

## Reports

A callback is named after the function that hands it over, so the call history reads from the
name alone.

Reporting unit: Each function whose name ends in a callback suffix.

Anchor: The function name.

Carve-outs: A function whose name ends in `_callback` or `Callback` is a callback, and the text
before the suffix is the caller it claims. It reports when no function in the same file carries that
name, so `read_sector_callback` beside `read_sector` is quiet and a `write_callback` that `flush`
hands over reports. A function the file calls by that name carries it too, whether the call is free,
`write()`, or a method call, `disk.write()`. A function named `callback` or `Callback` with nothing before the suffix is
quiet. A function the file calls directly and never hands over as a value is a helper whose name
happens to end in the suffix, such as `hooked_callback` checking the callback argument of a hook,
and is quiet. A direct call includes a member call the file spells by the function's name,
`surface.colorSchemeCallback(scheme)`, so a method the file invokes on a value is a helper too.

The style's sentence starts from one calling function: "When a single function calls out to a helper
function or callback". A callback reports only when exactly one function in the file hands it over
as a value, by name, through its container, or through the closing brace of the anonymous container
that declares it, `struct { fn grid_ready_callback(...) }.grid_ready_callback`, with or without
parentheses that wrap exactly the container. A function the file never hands over has no caller the
file can show, since its hand-over, if any, is in another file, so a public method such as
`Surface.sizeCallback` that other files call is out of scope. A callback that two or more functions
hand over, a timer callback armed in one function and re-armed in another, has no single caller to
be named after and is quiet. A callback handing itself over again from its own body does not count
as a second caller. A callback whose name opens with the name of the one function that hands it over
carries that caller's name as the style asks, since the sentence asks for the caller's name as a
prefix. The names are compared word by word with case ignored, so `scan_lookup_callback` handed over
by `scan`, `scanLookupCallback` handed over by Go's exported `Scan`, `noopCallback` returned by the
type function `NoopCallback`, or `commit_checkpoint_data_grid_callback` beside
`commit_checkpoint_data_aof_callback`, both handed over by `commit_checkpoint_data`, is quiet; the
words between the caller's name and the suffix tell the caller's callbacks apart.

A declared function is the only kind read: a callback bound to a variable, a parameter named
`callback`, and a function in another file are out of scope, and so is a procedure with no body, an
Odin procedure type `Bad_Free_Callback :: proc(memory: rawptr)` or a `foreign` declaration ending in
`---`.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS057, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

There are none recorded.

## Citations

TigerStyle: "When a single function calls out to a helper function or callback, prefix the
name of the helper function with the name of the calling function to show the call history.
For example, `read_sector()` and `read_sector_callback()`."
