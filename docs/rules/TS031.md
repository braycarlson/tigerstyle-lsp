# TS031 comment-form

The severity is info; the rule is opt-in by default and stable.

## Reports

A comment is written as prose: a space after the marker, a capital letter at the start, and a
full stop at the end.

Reporting unit: Each sentence for the capital and the full stop, and each comment line for the
space. A run is a group of consecutive own-line comments sharing a start column; a line whose body
ends with `.`, `!`, or `?` closes a sentence, so the next line in the run opens a new one and is
checked for its capital, while a line that ends without a terminator continues its sentence into the
next line, which is then not checked for a capital. A line that is not prose closes the sentence
before it.

Anchor: The three insertion points rather than the comment token: the byte after the marker for the
space, the first alphabetic character for the capital, and the byte past the body for the
full stop; the colon itself when nothing follows it.

Carve-outs: A comment sharing its line with code, before it or after it as in `/* seed */
0x2ce57620,`, is checked for the space after its marker only, since the standard lets a trailing
comment be a phrase with no punctuation. A multi-line block comment is exempt. A body is not prose,
and so is skipped, when it is empty, when it is indented four or more spaces, which is commented-out
code, when it opens with a per-language directive prefix, when it carries a bare URL, a `://`
outside the target of a Markdown link `[text](https://...)`, when it opens with a list-item or
heading prefix (`- `, `* `, `+ `, `> `, `| `, `# `) or a Markdown heading of any level, one to six
`#` and a space as in `//! ## Design`, when it opens a code fence with three backticks or sits
inside one, or when it ends with a code terminator (`;`, `{`, `}`, `(`, `)`, `[`, `]`, `=`). There
are three endings that are not code terminators: a line whose inline code span is still open, ``Note
that `at ==``, ends inside the span, a `)` that closes a parenthesis opened after a space or a
Markdown link, `an inductive (i.e., recursive)` or `[docs](https://...)`, closes a remark rather
than a call such as `int foo(int bar)`, and a `]` that closes a code link, ``a [`TriangleList`]``,
ends a link in the middle of a sentence. Such a line is never checked itself, but it carries the
sentence across it, so the line before it is no paragraph end and the line after it is no paragraph
opening. The directive prefixes are Rust `clippy` and `rustfmt`; Go `+build`, `go:`, `lint:`, and
`nolint`; Zig `zig` and `zig fmt:`; and Python `!`, `-*-`, `coding:`, `fmt:`, `isort:`, `mypy:`,
`noinspection`, `noqa`, `nosec`, `pylint:`, `pyright:`, `ruff:`, and `type:`. A doc marker (`/` or
`!` after `//`, in Rust and Zig) is peeled and the body checked like any other, so a doc comment is
in scope in both languages; a doc comment is a comment. The terminator set is `.`, `:`, `!`, and
`?`. A sentence closing with a colon must relate to something that follows, so the next line must
exist, hold text, open with no closing bracket, and sit at no shallower indentation than the
comment; otherwise the colon reports.

A one-token body carrying `:`, `/`, `_`, or `-`, such as `noqa:E501` or a path, is a marker
rather than prose and is skipped, as is a body opening with `..`, which is a Sphinx directive.
A one-token body that opens with `[` or closes with `.`, `!`, or `?`, such as
``[`Config::prefilter`].``, is a link closing a sentence and stays prose.
Python's `#:` attribute doc marker is peeled like a doc marker.

A line indented two or three spaces under a list item, in the same run, continues the item's
sentence rather than opening one, so `///   due to appends.` under `/// - Let A be the maximum`
is not checked for a capital, while the full stop is still checked where that sentence closes.
A Markdown link reference definition, `/// [label]: crate::task#cancellation`, is
data rather than prose and is skipped. A line closing with `.)`, `!)`, or `?)` ends its
sentence inside a parenthesis rather than ending in a code terminator, so the sentence that
runs onto it is not cut short a line early; an ellipsis before the parenthesis, `...)`, stays
a code terminator.

## Does not report

The rule reaches every language tigerstyle-lsp lints.

A finding is suppressed by a `tigerstyle-ignore:` directive naming TS031, by a
`tigerstyle-file-ignore:` directive, or by a `tigerstyle-disable:` region covering the line.

## Known false positives

The shapes that misfire here are `byte-column` and `block-comment-one-liner`.

## Citations

TigerStyle: "Comments are sentences, with a space after the slash, with a capital letter
and a full stop, or a colon if they relate to something that follows. Comments are
well-written prose describing the code, not just scribblings in the margin. Comments after the
end of a line _can_ be phrases, with no punctuation."
